检索记忆救不了秘密状态；私有工作记忆让 Hangman 满分

Retrieval memory cannot preserve hidden state; private working memory makes Hangman agents self-consistent.

标准 chat 只看公开历史。可是在 Hangman、诊断问答这类任务里，agent 必须先私下选定一个秘密，再在后续轮次里始终按同一个秘密作答。现有 RAG、Mem0、A-Mem 这类记忆，主要是在公共对话里检索和摘要，不会把新生成的私有状态稳稳保住，所以“记得过去”并不等于“保住秘密”。

关键动作是把记忆拆成一个显式的 private working memory，并在每轮把它重新注入 prompt（用 <private_state> 包住）。作者把 agent 分成 Autonomous 和 Workflow 两类，再配 Overwrite、Append/Delete、Patch/Replace-in 三种更新法；同时先形式化 POCA 与 PSIT，并证明只依赖公共历史的 agent 不可能同时保持“公开 transcript 不泄密”和“对固定 hidden state 一致”。

实验证明这不是纸面问题。作者在 Hangman 和 Diagnosis Simulator 上，用 GPT-OSS 20B/120B、Qwen3 32B/235B 各跑 $50$ 次，并在 $t_{fork}=4$ 分叉做 self-consistency 测试。Vanilla LLM 和四个检索式 memory baseline 都很低；而 Workflow + Overwrite/Patch 接近满分，例如 Hangman 上 Qwen3-235B 达到 $100\%$，Diagnosis Simulator 上 GPT-OSS 120B 达到 $96\%$；Private CoT 也高，但代价是约 $10\times$ 的上下文。

这篇论文把问题说清了：对 PSIT 来说，memory 不是检索仓库，而是要能生成并保留新的私有状态。它也暴露出两个边界：证据只来自两类 forked 任务，且私有状态仍是文本块注入 prompt，离更复杂的长期 agent 还有距离。

Standard chat agents only condition on public history, so they can stay consistent when the state is visible but not when a task requires a secret that must remain hidden. Hangman and diagnosis-style interactions expose that gap: the model has to commit privately, yet the transcript cannot reveal the commitment. Existing memory systems mostly retrieve or summarize public conversation, which helps recall but does not preserve freshly generated private state.

The paper’s move is to define Private State Interactive Tasks (PSITs) and prove that public-only chat agents cannot satisfy both public underdetermination and hidden-state consistency. It then adds an explicit private working memory, injected each turn as a hidden <private_state> block. The authors test two control regimes, Autonomous Memory Agents and fixed Memory Workflows, and three update operators: overwrite, append/delete, and patch/replace-in.

On Hangman and Diagnosis Simulator, they run GPT-OSS 20B/120B and Qwen3 32B/235B for $50$ episodes per setting, with self-consistency checked after forking at $t_{fork}=4$. Vanilla LLMs and four retrieval-based memory baselines stay low across the board. The workflow-based private-memory agents are the strong performers: Qwen3-235B reaches $100\%$ on Hangman, GPT-OSS 120B reaches $96\%$ on Diagnosis Simulator, and the Private CoT upper bound is close but bloats the context by about $10\times$.

The main takeaway is narrow but important: if a task needs a hidden state that survives dialogue turns, retrieval is not enough. The paper makes that point cleanly. The catch is that the evidence comes from two synthetic forked tasks, and the proposed memory is still a text block in the prompt, so we do not yet know how far this extends to richer real-world agents.

Agent 失败难在定位：轨迹长、工具输出噪，错误会级联，最后看到的常是症状不是根因。现有评测多报终局成功率，或把后面的症状当成最早断点；人工归因对长轨迹也太贵，170 条标注就要 62.5 小时。

AgentRx 的关键动作是把异构日志先归一成 IR，再从 tool schema、domain policy 和前缀 $T_{\leq k}$ 合成全局约束 $\mathcal{C}^{G}$ 与动态约束 $\mathcal{C}^{D}_{k}$。约束带 guard$G_{C}$ 和 assertion$\Phi_{C}$，逐步检查后写入验证日志 $\mathsf{V}$；LLM judge 再结合 $\mathsf{V}$ 和 taxonomy checklist$\mathsf{K}$，选出 $\hat{s}$ 和 $\hat{y}$。

在 170 条失败轨迹、11 个任务设置上，它把根因定位和分类都做成可复核的轨迹证据。与 W&W∗比，$\tau$-bench 的 step acc 从 18.8 提到 42.7，Magentic 从 22.7 到 36.4，Flash 从 64.3 到 82.5，RelWork 从 32.6 到 61.5；论文概括为平均 step localization 提升 75%，root-cause categorization 比 judge baselines 提升 30%。在 30 条样本上，三位标注者的 pairwise$\kappa$ 为 0.93、0.87、0.90，均值 0.89。

这说明轨迹级约束是有用信号，但也有脆弱处：taxonomy 可能漏掉别的 agent 场景，弱或带假阳性的 violation 会把 judge 带偏。一步步生成约束比一次性更准，尤其长轨迹上更明显，但 one-shot 也要 $0.18$ 美元/条，约是 baseline 的 $3.6\times$；它更适合把 agent 调试从“看结果”推进到“看哪里开始回不去”。

Agent failures are hard to localize because trajectories are long, tool outputs are noisy, and one mistake cascades into later symptoms. Existing evaluations often stop at terminal success, or they label the wrong step; manual attribution is also too expensive once traces get long.

AgentRx’s move is to normalize heterogeneous logs into an IR, synthesize global constraints $\mathcal{C}^{G}$ from tool schemas and domain policies plus dynamic constraints $\mathcal{C}^{D}_{k}$ from the prefix $T_{\leq k}$, then check guarded assertions $G_{C}$/$\Phi_{C}$ step by step. The violations are written into an auditable log $\mathsf{V}$, and an LLM judge uses $\mathsf{V}$ plus checklist $\mathsf{K}$ to pick the critical step $\hat{s}$ and category $\hat{y}$.

On 170 failed trajectories across 11 task settings, AgentRx gives evidence-grounded localization and attribution. Against W&W∗, step accuracy moves from 18.8 to 42.7 on $\tau$-bench, 22.7 to 36.4 on Magentic, 64.3 to 82.5 on Flash, and 32.6 to 61.5 on RelWork; the paper summarizes this as 75% average step-localization improvement. Root-cause categorization improves by 30% over judge baselines. On 30 annotated trajectories, pairwise $\kappa$ is 0.93, 0.87, and 0.90, for a mean of 0.89.

The useful part is that failures become inspectable, not just scored. The weak spot is equally clear: the taxonomy may miss other agent domains, and noisy or downstream violations can mislead the judge. Step-by-step constraint synthesis is more accurate on long traces, but one-shot costs USD 0.18 per trajectory, about $3.6\times$ the $0.05$ baseline, so the practical choice is between cheaper monitoring and better debugging.

Most coding agents reuse the same fragile stack: tools, prompts, and context assembly keep the same failure modes from one task to the next. If you let the agent rewrite itself, the harder problem becomes safety, because the runtime must stay controlled while the system keeps changing.

Ouroboros makes evolution part of the loop. Reviewed commits become the runtime for later work, so improvements to tools, prompts, context assembly, and core implementation can be deployed only after human review. It uses two modes: recursive free evolution, where completing one evolution cycle can schedule the next, and experience-driven core evolution, where bugs and rough edges found during ordinary work or social interaction trigger structural changes.

The abstract reports three headline results. On Terminal-Bench 2.1, an Opus 5 run scores 86.74%, described as the best result reported on that benchmark. On OSWorld-Verified, an Opus 5 run reaches 90.69%, above the previous best. On CL-Bench, a five-rollout campaign achieves a normalized reward of 0.2301 and sets a new state of the art.

The paper’s main point is not just that the agent learns, but that the learning pipeline is itself governed: benchmarks run on frozen snapshots, while Hope is a separate 161-day live lineage under human communication across seven surfaces. What remains unclear from the abstract is how much of the gain comes from the self-development scheme versus the underlying Opus 5 backbone, and how stable the safety controls are under longer or more adversarial evolution.

Multi-turn agentic RL tends to collapse as trajectories get longer: rollout and training contexts drift apart, sparse terminal rewards give weak turn-level credit assignment, and optimizing short and long trajectories with different policy versions introduces asynchronous drift. Existing methods flatten the whole trajectory, which seems to amplify all three failure modes at once.

RTPO’s move is to represent rollouts as sparse reverse trees and update the policy in temporal reverse order at the turn level. That lets each decision be trained against its downstream continuation, which makes credit assignment causally consistent and uses on-policy continuation to suppress policy drift between short and long trajectories.

The abstract reports theoretical claims rather than implementation details: under this formulation, RTPO is said to remove context mismatch and asynchronous drift, reduce credit bias, and converge to recursive optimality. On multi-turn agentic RL benchmarks, it improves over trajectory-level baselines by $21.50\%$ and over turn-level baselines by $10.76\%$.

The contribution is not another reward tweak; it reframes multi-turn agent training as an ordering problem in optimization. But with only the abstract, it is impossible to judge the cost of the reverse-tree machinery, the trajectory lengths it supports, or whether the gain depends on a narrow benchmark suite.

关键动作是把 harness 训练拆成两层：CAPO 先用前向激活找出更偏 Action 或 Args 的层/单元，再把对应 token 的梯度路由到各自参数子空间；黑盒 RL 则记录 Interface Call Record，按会话建 prefix tree，把真实调用重建成对齐样本，并把 outcome reward 和 process reward 贴回可训练 token。

在 2WikiMultiHopQA 和 HotpotQA 的 RL queries 上，作者评了 2WikiMultiHopQA、HotpotQA、Bamboogle、FRAMES、MuSiQue、NQ、TriviaQA 七个 benchmark。Harness-RL 在 Qwen2.5-1.5B/3B 上的平均 token-F1 分别是 42.93 和 47.79，分别比最强 baseline AgenticRAG-R1 高 15.28 和 14.24 分；去掉 CAPO 后降到 41.04 和 46.22。

Most agentic RL methods still treat Action and Args as one stream, so a bad query string can poison the gradient for an otherwise correct dispatch decision. The second failure mode is structural: a central agent plus sub-agents, tools, and environment feedback generates branching, concurrent, and rewritten contexts that do not collapse cleanly into one token line. Flattening that structure hides who actually caused the reward and makes training brittle.

Harness-RL splits the problem in two. CAPO uses forward activations to estimate which layers are more Action-like or Args-like, then routes gradients from each token type into the matching parameter subspace. In parallel, the black-box RL side records Interface Call Records, rebuilds session-wise prefix trees, and turns real harness interactions into aligned samples with outcome and process rewards attached to trainable tokens. That keeps the harness black-box while still doing token-level credit assignment.

On RL queries drawn from 2WikiMultiHopQA and HotpotQA, the paper evaluates seven benchmarks: 2WikiMultiHopQA, HotpotQA, Bamboogle, FRAMES, MuSiQue, NQ, and TriviaQA. With Qwen2.5-1.5B and Qwen2.5-3B, Harness-RL reaches average token-F1 of 42.93 and 47.79, beating AgenticRAG-R1 by 15.28 and 14.24 points. Removing CAPO drops the averages to 41.04 and 46.22, so the gradient routing is not just cosmetic.

The clean read is that structured credit assignment matters more than just more rollouts. The paper also concedes that CAPO is not uniformly helpful across datasets, and that central-only training beats all-agent training on the 3B setup, 47.79 versus 45.36. For agent work, the contribution is concrete: it turns tool use, planning, and multi-agent coordination into a trainable RL problem, but it is only shown on Qwen2.5-1.5B/3B and central-coordination QA/retrieval tasks, so broader harnesses remain untested.

References in collaborative chat are often indirect, so resolving “this looks like the fix discussed yesterday” means joining conversational cues with workspace evidence. Standard retrieval benchmarks miss that because they do not force an agent to move back and forth between dialogue, metadata, and content, or to eliminate near-miss candidates.

The paper names this setting Conversational Reference Grounding, or CoRG. Given tools, the task is to map a reference in conversation to the unique external item the speaker intended. The core move is multi-step tool use: search for plausible candidates, inspect metadata and contents, and rule out alternatives until one item remains.

RepoRef instantiates CoRG with 400 developer-chat segments grounded in GitHub issues, pull requests, and commits across 92 repositories. The abstract reports only the headline outcome: the best agent reaches 67.0% success rate, so one third of references still remain unresolved.

That makes the benchmark useful as a stress test for search, inspection, and verification in realistic tool environments. But with only the abstract, it is still unclear where systems fail most, whether the benchmark favors certain repositories or reference types, or how much of the gap comes from retrieval versus planning versus evidence checking.
