Training Proactive and Personalized LLM Agents

PPP 用多目标 RL 兼顾问答与偏好，平均+16.7 分

PPP trains LLM agents with multi-objective RL, lifting the average score by 16.7 points while improving questions and preference following.

现有 LLM agent 多只盯任务成功，遇到含糊指令时既不主动澄清，也不顾用户偏好。结果是 benchmark 分数能高，交互却常把用户当信息源，问得少、问得差。

关键动作是把“会不会协作”变成训练目标：UserVille 先把精确 prompt 做 vaguenization，再用带偏好的 user simulator 通过 ask_user tool 和 agent 多轮交互。训练时把 $R_{\text{Prod}}$、$R_{\text{Proact}}$、$R_{\text{Pers}}$ 相加，用 GRPO 优化；前者管任务成功，后两者分别按 query effort 和偏好遵循计分。

在 SWE-Bench Verified (Func-Loc) 和 BrowseComp-Plus 上，PPP 相比 Seed-OSS-36B 的平均分从 45.32 提到 62.04，+16.72。含糊提示下，SWE-Func-Loc 的 F1 从 44.11 到 64.50；问句策略也更像“只在必要时问”，在 SWE 上 ask ratio 50%→100%，在 Deep-Research 上 51%→85%。

更重要的是，它不只学会多问，而是学会问得更省事：用户研究里 PPP-36B 的 overall score 是 3.75，接近 GPT-5 的 3.79，高于 Seed-36B 的 3.45。不过这些收益仍依赖合成 user；论文也指出 effort 估计有 sim-to-real gap，且模型主要在 SWE-Func-Loc 上训练，到了 SWE-Full 只从 0.29 升到约 0.36。

Most LLM agents are still optimized for isolated task success. When instructions are vague, they either stay silent or ask the wrong questions, so benchmark wins hide missed clarification, ignored preferences, and unnecessary user effort.

The trick is to make collaboration a training signal. UserVille first converts precise prompts into vague ones, then pairs the agent with preference-parameterized user simulators through an ask_user tool. Training maximizes $R_{\text{Prod}}+R_{\text{Proact}}+R_{\text{Pers}}$ with GRPO; productivity covers task success, while the other two terms score question effort and preference adherence.

On SWE-Bench Verified (Func-Loc) and BrowseComp-Plus, PPP raises the average score from 45.32 to 62.04 over Seed-OSS-36B, a gain of 16.72 points. Under vague prompts, SWE-Func-Loc F1 climbs from 44.11 to 64.50. The policy also learns to ask selectively: ask ratio goes from 50% to 100% on SWE-Func-Loc and from 51% to 85% on Deep-Research.

The user study matters because it tests whether simulated users transfer to people. In a Prolific study with 33 programmers on 100 SWE-Bench Verified tasks, PPP-36B reaches an overall score of 3.75, close to GPT-5’s 3.79 and above Seed-36B’s 3.45. But the gains still lean on synthetic users, the effort signal has a sim-to-real gap, and the model was trained mainly on SWE-Func-Loc, where transfer to SWE-Full only lifts success from 0.29 to about 0.36.

core idea

ST-EVO: Towards Generative Spatio-Temporal Evolution of Multi-Agent Communication Topologies

用流匹配调度器做时空协同，自进化 MAS 准确率提升约 5%–25%。

静态通信模板把多智能体协作锁死了：只做空间演化，或只按时间滚动重排，都还在单一维度里调度，难以把协作能力逼出来。摘要里的问题是，现有 self-evolving MAS 还没同时处理“谁和谁说”和“什么时候说”。

ST-EVO 的关键动作，是把通信拓扑的生成放到一个紧凑的 flow-matching Scheduler 里，按 dialogue 级别同时决定空间连接和时间顺序。它还显式建模 MAS 的 uncertainty，并加入 self-feedback，让系统能从累计经验里继续修正调度。

作者说在九个 benchmark 上做了 extensive experiments，结果达到 state-of-the-art，accuracy 相比基线提升约 $5\%$–$25\%$。但摘要没有给出各数据集、任务类型、基线名和具体数值，因此现在只能确认总体幅度，不能判断提升主要来自哪一块。

这篇对 agent 方向的相关性很直接：它不是在改 prompt，而是在改多智能体通信协议本身，并试图把规划、调度和经验回流合到一条链里。问题是证据只在摘要层面，真正的收益稳定性、代价和对更强基线的鲁棒性都还看不到。

Static communication templates trap multi-agent systems in fixed interaction patterns. Prior self-evolving work usually edits either the topology or the timing, but not both, so it still leaves part of the coordination problem untouched.

ST-EVO’s move is to generate communication at the dialogue level with a compact flow-matching scheduler that jointly decides who talks to whom and when. It also models MAS uncertainty and adds self-feedback, so the scheduler can revise its policy from accumulated experience instead of treating each episode as independent.

The abstract claims state-of-the-art results on nine benchmarks, with accuracy gains of roughly 5%–25% over baselines. That is a meaningful range, but the abstract does not name the tasks, baselines, or exact scores, so the strength of the claim cannot be checked from the text alone.

For agent research, the paper matters because it targets the communication protocol itself rather than prompt tuning. The limitation is simple: with abstract-only evidence, it is still unclear whether the gains come from the spatio-temporal formulation, the uncertainty signal, or the self-feedback loop, and whether the method scales beyond the reported benchmarks.

LLM agent 一旦进入长任务流，记忆就不再只是检索缓存，而会把错误轨迹、偶然成功和过时记录一起放大。现有做法要么只在入库时筛一遍，要么只靠 retrieval，结果是错误记忆被写入后继续污染后续决策，冲突和陈旧条目也会在长期运行中堆积。

MemGuard 的关键动作，是把 verifier 输出从一次性过滤器改成贯穿生命周期的元数据。它把多指标 score-token verification 转成 reward、confidence、label 和 uncertainty，先附着到每个候选记忆上，再在激活、retrieval、冲突消解、summarization 和 archival 各阶段复用；也就是说，验证信号不只决定“能不能进库”，还决定“进库后怎么被用”。

作者在 Terminal-Bench 2.0、SWE-Bench Verified、WebArena 和 Mind2Web 上，用四个 backbone、四个 memory baseline 和一个 verifier-only control 做了对照，并且限制在匹配的 runtime budget 下。摘要给出的结论是：在 16 个 backbone-benchmark 组合里，MemGuard 都拿到最好的 success metric 和最低的 average steps；相对最强的 memory baseline ReasoningBank，WebArena 的 success-rate 高 7.9 点，Mind2Web 的 step-success-rate 高 5.6 点，terminal 和 software-engineering 基准上高 2.4–3.5 点。

这说明问题不在于记忆“有没有”，而在于记忆能否持续携带可信度和冲突信息。它对 agent memory governance 很贴题，但摘要还没告诉我们各个 backbone 是什么、score-token verification 具体怎么训练、以及这些提升在 verifier 质量变化时是否稳健；另外，只有摘要，无法判断 baselines 是否足够强。

When LLM agents run for hundreds of steps, memory stops being a convenience layer and becomes a failure amplifier. Bad trajectories get stored because they look relevant, lucky outcomes look like good policy, and retrieval alone does not fix stale or conflicting records.

MemGuard’s move is to treat verifier output as persistent lifecycle metadata instead of a one-shot gate. It converts multi-criteria score-token verification into reward, confidence, label, and uncertainty fields, attaches them to each candidate memory before activation, and reuses them during retrieval, conflict resolution, summarization, and archival.

The paper evaluates this on Terminal-Bench 2.0, SWE-Bench Verified, WebArena, and Mind2Web with four backbones, four memory baselines, and a verifier-only control under matched runtime budgets. Averaged over five seeds, MemGuard gets the best success metric and the lowest average steps in all 16 backbone-benchmark settings. Against ReasoningBank, its strongest evaluated memory baseline, it gains 7.9 success-rate points on WebArena, 5.6 step-success-rate points on Mind2Web, and 2.4-3.5 points on the terminal and software-engineering benchmarks.

The paper’s real claim is that memory quality depends on preserving verifier evidence through the whole memory lifecycle, not just admission. That is directly relevant to agent memory systems. The abstract leaves open how the four backbones differ, how score-token verification is implemented, and whether the gains survive weaker or stronger verifiers; with abstract-only evidence, that uncertainty matters.

Automated MAS evolution is stuck in a trade-off: expand the search space and stability drops; use branch-and-discard search, and useful insights stay trapped in separate lineages. In practice, handcrafted systems still tend to win.

OptiMAS changes the move from search to continuous optimization. It builds on a shared ReAct infrastructure, treats prompts, skills, tool configs, and orchestration as part of $\mathcal{E}$, runs the system on $\mathcal{X}_{\text{train}}$ and $\mathcal{X}_{\text{val}}$, and feeds full trajectories plus $R_{\text{train}}$ and $R_{\text{val}}$ back as textual gradients. Across four benchmarks and three backbones, OptiMAS beats the initial $\mathcal{E}_0$. 过去的 agent 自演化默认一件事：把成功轨迹蒸馏成 skill memory，之后检索得越多，解题越稳。作者的 probe 发现这在工具调用上会反过来伤人：任务像旧题但工具需求已变时，更多被检索的技能会抬高错误工具调用的置信度，形成 Skill Imitation Trap。

BASM 的关键动作，是不给技能只存“怎么做”，而是补上边界字段：适用条件、风险提示、回避规则和恢复笔记。这样检索到的 skill 不是无条件动作模板，而是 state-conditioned guidance：条件满足时才执行，条件不符时压住不该用的工具，失败后按恢复笔记做定向修补。

摘要只给出总体结果：在三个 agent benchmark 和四个 model scale 上，BASM 都优于只从成功轨迹蒸馏的 skill-memory baseline。它在 AppWorld 的 task success rate 最高提升 $23.8 ext{%}$，在 BFCL 的 accuracy 最高提升 $5.0 ext{%}$，在 AgentDojo 的 attack success rate 降低 $4.6 ext{%}$，同时相对 memory-free baseline，AppWorld 的平均 steps 最多减少 $6.6 ext{%}$。

这篇工作的意思很直接：对工具型 agent，记忆不是越像示范越好，边界信息可能比动作本身更关键。摘要里看不到分桶分析、消融和检索细节，所以还不能判断这些增益主要来自哪里，也不能排除某些 benchmark 更吃这种边界标注。

Agent self-improvement usually assumes that distilling successful trajectories into memory will help monotonically. The abstract says that assumption breaks for tool use: when a task looks like a past success but needs a different tool, retrieving more skills can actually raise confidence in the wrong call. The authors call this the Skill Imitation Trap.

BASM changes the memory item itself. Instead of storing only an action pattern, each skill is annotated with applicability conditions, risk cues, avoidance rules, and recovery notes. Retrieved skills then act as state-conditioned guidance: use the skill when the condition matches, suppress the tool call when it does not, and repair the execution when it fails.

On three agent benchmarks and four model scales, BASM beats success-distilled skill-memory baselines throughout. The abstract reports up to $23.8\%$ higher task success on AppWorld, up to $5.0\%$ higher accuracy on BFCL, and a $4.6\%$ drop in attack success rate on AgentDojo; compared with a memory-free baseline, average AppWorld steps drop by up to $6.6\%$.

The main takeaway is that tool-use memory needs boundaries, not just exemplars. But this is only from the abstract, so the stronger claims are still hard to judge: there is no visibility into ablations, retrieval behavior, or whether the gains come from better calibration, better tool selection, or both.

部署中的 LLM agent 把 memory 变成默认组件后，新的风险不再是“会不会记住”，而是“谁能把记忆写成后门”。现有系统通常按 retrieval-then-generate 工作，但也因此把检索到的记忆条目直接喂给生成器，攻击面随之外露。

InjecMEM 的关键动作，是把一次交互构造成“锚点+命令”两段式注入。锚点用高召回的主题线索，尽量让后续相关查询稳定检索到这条记录；命令则是经梯度坐标搜索得到的短序列，目标是在 fused contexts、不同插入位置和长 prompt 下都还能把输出推向预设答案。作者还把命令做成跨 backbone 的联合优化，以观察迁移性。

摘要称它在多个 memory systems 和 backbone 上都能实现可靠的 topic-conditioned retrieval 和 targeted generation，并且在 memory drift 下仍有效，同时对非目标查询影响不大。这里的证据是跨系统、跨模型的攻击可重复性，而不是单一实现上的偶然脆弱点。

这篇工作对 agent memory 很重要，因为它把威胁从“读出隐私”推进到“写入偏置”。但目前只有摘要，无法判断比较基线、具体成功率、以及是否覆盖真实部署里的防护与更新机制；因此更像一套可复现的攻击范式，而不是已被充分定量化的系统性结论。

Once memory becomes a default subsystem in deployed LLM agents, the issue is no longer just what gets remembered, but who can turn memory into a backdoor. Because these systems often retrieve stored items and then generate from the fused context, the retrieval step itself becomes the attack surface.

InjecMEM’s trick is a two-part injection: an anchor plus a command. The anchor uses high-recall topical cues so later related queries keep retrieving the planted record; the command is a short sequence optimized by gradient-based coordinate search to survive fused contexts, variable insertion positions, and long prompts while still steering the answer once retrieved. The authors also jointly optimize the command across backbones to test transfer.

From the abstract, the attack works across multiple memory systems and backbone models, giving reliable topic-conditioned retrieval and targeted generation. It also remains effective under memory drift and leaves non-target queries largely unaffected, so the main claim is cross-system robustness rather than a brittle single-model exploit.

For agent memory research, the paper shifts the concern from leakage to poisoning. But with abstract-only evidence, the exact success rates, baselines, and defensive coverage are unknown, so this is best read as a reproducible attack framework, not a fully characterized threat model.

轻量 forecaster 的问题不是模型不够小，而是少样本就会迅速过拟合；但私有、慢积累的时间序列域往往拿不到足够历史。现有 LLM-as-Forecaster 和 Agent-as-Forecaster 仍卡在离散 token 到连续数值的模态鸿沟，TSFM 又常常太重，部署成本和数据门槛一起上升。

MetaCaster 的动作不是让 agent 直接报预测，而是先把 $K$-shot support set $\mathcal{D}_{\text{sup}}^{m}$ 和文本上下文 $\mathsf{C}_{m}$ 变成可训练数据 $\bar{\mathcal{D}}^{m}$。MGagent 生成数据，FTagent 在 LT-Lib 里训练和筛选 23 个 lightweight forecasters，HPagent 只优化 MGagent 的 harness；它用 $\delta(\omega(f_l^m),\omega(\bar f_l^m))=\max\{\frac{\omega(\bar f_l^m)-\omega(f_l^m)}{\omega(f_l^m)},0\}$ 反馈，把目标从“像不像原数据”改成“下游预测准不准”。

实验用 GIFT-Eval 的 18 个数据集、9 个 domain，设 $K\in\{10,30,50\}$，对比 14 个基线。Table 1 里 MetaCaster 多数行都赢生成/增强方法；比如 ETTm1 在 $K=30$ 时是 0.345 MSE，优于最强基线 Jitter 的 0.662。Solar 上还报告，在相近性能下它可做到 $10^3$ 倍更低 latency 和 $10^5$ 倍更少参数。

这更像 agent-as-engineer：agent 负责造数据和搭训练管线，最后只把选中的轻量 forecaster 留给推理。短板也明确：它不做 zero-shot，只在 18 个数据集上验证，LT-Lib 也只是作者整理的 23 个模型；评估主要靠下游 MSE/MAE，不能单独证明生成序列本身有多逼真。

The bottleneck is not prediction speed. Lightweight forecasters still need enough target-domain history to avoid overfitting, but in private or slowly accumulating domains that data often does not exist. Direct LLM-as-Forecaster and Agent-as-Forecaster systems still run into the modality gap, while TSFMs are too heavy for the deployment regimes this paper targets.

MetaCaster’s move is to stop the agent from forecasting directly. Given a few-shot support set $\mathcal{D}_{\text{sup}}^{m}$ and context $\mathsf{C}_{m}$, MGagent synthesizes a larger training set $\bar{\mathcal{D}}^{m}$, FTagent trains and selects among 23 lightweight forecasters in LT-Lib, and HPagent tunes the MGagent harness with a hinge-style objective $\delta(\omega(f_l^m),\omega(\bar f_l^m))=\max\{\frac{\omega(\bar f_l^m)-\omega(f_l^m)}{\omega(f_l^m)},0\}$. The point is to optimize downstream forecast quality, not raw data realism.

On GIFT-Eval, across 18 datasets in 9 domains and $K\in\{10,30,50\}$, MetaCaster beats generation and augmentation baselines in most rows. The clearest single-number example is ETTm1 at $K=30$: 0.345 MSE versus 0.662 for the best non-MetaCaster baseline, Jitter. The paper also reports that, on Solar at comparable performance, MetaCaster can reach $10^3$ times lower latency and $10^5$ times fewer parameters than TSFMs.

The result is a plausible Agent-as-Engineer pipeline for TSF, but the scope is still narrow. The method is not zero-shot, so it needs at least a small reference set; the experiments cover 18 datasets rather than a broader pretraining corpus; and LT-Lib contains the 23 forecasters the authors assembled, not an exhaustive universe. The evaluation also validates utility through MSE and MAE, not the fidelity of generated series on its own.
