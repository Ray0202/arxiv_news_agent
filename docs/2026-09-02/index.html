农场 agent 最容易犯的错不是不会调工具，而是把时序和空间顺序做对了、把农时做错了：迟一天灌溉、早一天收割，最后都变成产量损失。过去的 geospatial agent 多半默认反馈快、动作边界清楚，拿来做全季农事会低估延迟效应、局部可观测性和生物过程的累积后果。

关键动作是把天气、遥感、UAV、传感器、机械和管理干预都写成共享农场过程引擎里的事件，再在数字孪生里回放 agent，而不直接碰真农场。FAIRY 在这个事件流上接九个 controller、可检索的 agronomic skills library 和可选 A2A 编排，并用 KTC、BFCL、CORE 和 Yield Loss 同时看轨迹和产量。

作者用校准后的引擎重建 $18$ 个历史 plot、并构造 $100$ 个场景。物理引擎的产量与实收几乎都落在 $2\%$ MAE 内。全季 L3 上，Qwen 从 Zero Context 的 $22.3\%$ Yield Loss 降到 Expert Instruct 的 $4.6\%$；DeepSeek 从 $12.6\%$ 降到 $2.9\%$。LLM-as-an-Expert 只补回一部分 gap，层级技能库则把 KTC 推到 $97.2\%$ / $96.8\%$。

这说明农业 agent 不能只看 tool-call success，必须把时空正确性和最终产量绑在一起。KTC 的回归最贴近产量：RMSE $4.2$、斜率 $1.01$、$R^2$ $0.70$；BFCL 和 CORE 更像失效检测器。A2A 虽然省 token，却常丢失 specialist 状态。局限是：评测仍在校准 digital twin 里，oracle 只是专家参考，且单一大豆农场的外推还没验证。

Farm agents usually fail not because they cannot call tools, but because they get timing and spatial coupling wrong: irrigate a day late, harvest a day early, and the error only shows up as yield loss. Much of prior geospatial-agent work assumes quick feedback and bounded actions, so it understates delayed agronomic effects, partial observability across ridges, and the way biology compounds mistakes over a season.

The core move is to encode weather, remote sensing, UAV reads, sensors, machinery actions, and management interventions as events in a shared farm process engine, then replay the agent inside a calibrated digital twin instead of on the live farm. FAIRY layers nine controller backends, a retrievable agronomic skills library, and optional A2A orchestration on top of that event stream, and scores runs with KTC, BFCL, CORE, and Yield Loss.

The paper calibrates the engine on $18$ historical plot-level soybean scenarios and evaluates $100$ scenarios overall. The physics engine tracks real harvested yield closely, with nearly all cases within $2\%$ MAE. On held-out L3 runs, Qwen3.6-35B-A3B drops from $22.3\%$ Yield Loss under Zero Context to $4.6\%$ with Expert Instruct, while DeepSeek-V4-Flash drops from $12.6\%$ to $2.9\%$. LLM-as-an-Expert only closes part of the gap; the hierarchical skills library pushes KTC as high as $97.2\%$ for Qwen and $96.8\%$ for DeepSeek.

The practical point is that farm agents need temporal correctness, not just tool-call success. KTC is the best-calibrated trace metric here, with RMSE $4.2$, slope $1.01$, and $R^2$ $0.70$; BFCL and CORE are better at detecting failure than grading quality. A2A saves tokens but often loses specialist state. The weak points are equally clear: the system is still evaluated in a calibrated digital twin, the oracle workflows are expert references rather than proven optima, and generalization beyond this soybean farm is not tested.

现有 memory-augmented LLM agents 往往把历史当成“永远可检索”的平铺缓存。任务一长，检索就更慢、干扰更大，而且很多访问其实是重复的。作者把问题改写成：不是删不删记忆，而是记忆何时该变得难取、何时该被重新点亮。

关键动作是把 memory control 拆成读和写两条路径。读路径根据 agent uncertainty 和 memory buffer utility 决定是否查 memory，避免 always-on retrieval；写路径则只强化对生成当前 response 有贡献的 memories。这样记忆不是一锅平铺，而是形成层级结构：高层策略持续保留，细节按需重新加载。

摘要里给出的评测覆盖 static 和 dynamic long-horizon interaction benchmarks。结果是，Oblivion 优于 direct baseline 和 memory-augmented baseline，并且在 120K interaction spans 上把 token cost 最多降到 73%。

这篇工作的价值在于，它把 agent memory 从“存多少”推进到“何时读、何时写”的控制问题上。对长程 agent 很对路，但摘要没有给出具体 benchmark 名称、消融或误差代价，所以现在还只能确认它省 token、并声称能稳住性能，不能判断这种衰减控制在更难环境里有多稳。

Memory-augmented LLM agents usually treat history as always available. That makes retrieval expensive as contexts grow, and it also increases interference when irrelevant memories keep resurfacing. The paper reframes the failure mode: the problem is not simply what to store, but when memory should become harder to access and when it should be reactivated.

The core move is to split memory control into a read path and a write path. The read path decides whether to consult memory from agent uncertainty and memory buffer utility, instead of doing always-on retrieval. The write path reinforces memories that helped form the current response. The result is a hierarchical organization in which high-level strategies persist while details are loaded on demand.

The abstract says the method is evaluated on static and dynamic long-horizon interaction benchmarks. Oblivion outperforms both direct baselines and memory-augmented baselines, and at 120K interaction spans it reduces token cost by up to 73%.

The paper’s main contribution is conceptual and practical: memory is treated as a control policy, not a flat store. That is a good fit for long-horizon agents, but the abstract does not name the benchmarks, give ablations, or show whether the decay rule ever hurts recall-heavy tasks. So the win is credible on cost and promising on performance, but the robustness envelope is still unclear.

In long-horizon agents, memory writes get blamed for losses caused by downstream tool failures, noisy observations, or later reasoning errors. HiMPO’s move is to score each memory update by local utility: it compares what task-relevant information can be recovered from the pre-write and post-write memories under the same pre-write state. 多智能体 prompt 优化常把两件事搅在一起：一边生成任务内容，一边还承担路由、格式和终止信号这类执行协议。前者该被改，后者一旦被改坏，整条 agent pipeline 就会失效。现有做法的问题不是优化不够强，而是可优化对象本身把控制流和数据流混成了一团。

关键动作是做 control-data flow separation：把执行关键的 control 变成 typed、validated 的 program objects，把可变的任务语言留给 data flow 去优化。这样优化器只看到可改写的语言部分，不会直接接触路由和格式接口，因而能减少 prompt drift 对协议的破坏。论文强调，控制协议通常是结构化的，而任务内容通常是非结构化文本，这个表示差异就是分离的依据。

实验覆盖 synthetic reasoning、collaborative review generation 和 insurance rating workflows。摘要给出的唯一硬数是：框架实现了 $100\\%$ eventual protocol validity，同时持续提升任务表现。由于只有摘要，没法判断提升幅度、基线强弱，也看不到协议错误被消除到什么程度。

Multi-agent prompt optimization often entangles two different jobs: generating task content and enforcing execution protocols such as routing, formatting, and termination signals. That coupling is brittle. A prompt edit that helps generation can corrupt the protocol and break the whole pipeline. The core problem is not just bad optimization; it is that the optimized object mixes editable language with code-critical control.

The fix is control-data flow separation. Execution-critical control is moved into typed, validated program objects, while the optimizable part remains the task-language data flow used by agents to communicate. The optimizer then updates only the language side, so routing and formatting interfaces are protected from prompt drift. The paper’s rationale is simple: control is usually structured, while task content is usually unstructured text.

The abstract reports experiments on synthetic reasoning, collaborative review generation, and insurance rating workflows. The headline result is $100\%$ eventual protocol validity, alongside consistent task-performance gains. Because the input is abstract-only, there are no visible baselines, ablation details, or effect sizes for the performance gains.

The main takeaway is that stability in multi-agent prompt optimization may come from representation design, not just better search. That is directly relevant to agent systems that rely on fixed message schemas, routing rules, or stop conditions. The limitation is equally clear: with only the abstract, we can verify the protocol-validity claim but not how general the method is, how expensive it is, or whether the same separation works beyond the reported workflows.

Open-ended agent training gets stuck in two places: high-quality queries and expert rubrics are scarce, and the rewards are often brittle enough that long-horizon rollouts do not separate good behavior from bad behavior. That leaves vanilla RL with weak learning signals for reasoning and tool use.

ARISE-RL’s move is to close the loop between a Generator and a Solver with rubrics as the interface. The Generator must ground tool-related criteria in real tool observations, and it is rewarded for producing tasks that are valid and of intermediate difficulty, estimated from the Solver’s empirical success rate. The Solver then learns from rubric satisfaction, with partial credit plus a full-completion bonus. On top of that, RG-SED self-distills only when memory-augmented rollouts actually improve reward, using token-level reverse KL to keep the policy aligned with its own reward-validated guidance instead of blindly copying noisy suggestions.

The benchmark side is ECR-Bench, which pairs ECR-DeepResearch, a 100-query single-tool research set, with ECR-Travel, a five-way multi-tool planning suite covering Direction, Compare, Search, 1-Day, and M-Day. On Qwen3.5-9B, ARISE-RL reaches 0.569 average across the four reported benchmarks, versus 0.531 for Dr. Zero and 0.508 for Absolute Zero. It also posts 0.781 on ECR-DeepResearch, and the three self-evolution cycles improve all four benchmarks monotonically.

The result is a practical recipe for long-horizon agent RL: generate your own tasks, force them to be tool-grounded, and only distill memory when it demonstrably helps. The catch is scale. The paper only validates the recipe on 8B/9B open-source backbones, so the stability of the same loop on much larger models is still untested.

Small open agents often stall when long-horizon tasks are trained only from end-of-task verification. The paper argues the usual ceiling is not inherent to outcome-only RL; it comes from two practical failures. CANOPY addresses both with a deliberately minimal recipe.
