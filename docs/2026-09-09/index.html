现有 LLM agent 系统把 workflow、tools、token budget 和 prompt 做成固定模板，结果是同一套配置硬套所有查询：简单题浪费算力，难题又容易失配。摘要里说，这种“one size fits all”会带来脆弱行为和不必要的计算开销。

关键动作是把 agent 配置本身写成一个 SMDP 里的 temporally extended option，再用轻量级 hierarchical policy ARC 按查询选择配置。也就是说，系统不只决定“答什么”，还先决定“怎么组装并运行这个 agent”。

实验覆盖 reasoning、tool-use 和 agentic benchmarks。摘要给出的数字是：平均 reasoning accuracy 相对基线提升 31.3%，tool-use accuracy 提升 13.95%，$ au$-Bench (Airline) 的 Pass$^1$ success 从 9.0% 提到 18.0%。作者把这些结果解释为：按查询学习配置，优于预算匹配的 tool-augmented LLM。

这篇工作的价值在于，它把 agent 调参从人工模板推进到可学习的决策问题，尤其贴近长程规划、工具调用和预算控制。但摘要也只证明了跨基准的平均收益，没法判断在更大规模工具集、不同延迟约束或更复杂记忆模块下是否还稳；而且只有摘要，缺少配置空间、训练细节和消融，结论应保守看待。

Current LLM agent systems usually rely on fixed templates for workflows, tools, token budgets, and prompts. That one-size-fits-all setup wastes compute on easy queries and misconfigures hard ones, so behavior becomes brittle.

The key move is to cast agent configuration as a semi-Markov decision process, where each configuration is a temporally extended option. ARC is the lightweight hierarchical policy that chooses a query-specific configuration before the agent runs, so the system learns not only what to answer but how to assemble itself.

The abstract reports results across reasoning, tool-use, and agentic benchmarks. Compared with budget-matched tool-augmented LLMs, ARC improves average reasoning accuracy by 31.3%, tool-use accuracy by 13.95%, and doubles $ au$-Bench (Airline) Pass$^1$ success from 9.0% to 18.0%.

The practical point is that configuration can be treated as a policy problem rather than a hand-tuned heuristic. The evidence is promising but limited: the abstract does not expose the search space, training setup, ablations, or whether the gains hold under larger tool sets, tighter latency constraints, or richer memory components.

用户把关键参数省掉时，现有 personalized tool calling 多半还是在做 search：要么靠 profile/standing instruction，要么去 past calls 里捞同名参数。但很多偏好根本没被明说，甚至从未出现在目标函数里；这时，检索历史并不能补全 missing argument。

关键动作是把偏好当 latent variable 来推断。作者做了 MPT，把 SGD、DuRecDial 2.0、HomeBench 组成 4,695 个实例、459 段 multi-session histories，再按 Recall、Induction、Transfer 划分。PRefine 在 test time 维护一条文本化偏好假设，用 generate–verify–refine 迭代；只有能被累计行为记录支持、又能跨 session 解释新参数的假设才留下。

实验上，五个 LLM 上，PRefine 把 context-guided 的 macro average O-F1 从 58.17 提到 73.57，把 context-free 从 35.29 提到 60.55；在更难的 Transfer 上，macro average O-F1 也从 17.51 提到 32.31，而且它是唯一超过 Full-History Prompting 的方法。ablation 还表明，真正起作用的是 verifier，不是反复 refine。

这说明 personalized agent 的 memory 不能只是 archive，而要压成可复用的偏好假设。它也不便宜：PRefine 每个 session 8,855.57 tokens，低于 Mem0 的 9,424.11，也远低于 A-MEM 的 27,276.66。边界同样清楚：任务仍是 schema-bounded，且高 evidence interference 下 Transfer 仍最难。

Personalized tool calling still behaves like retrieval: either the user profile hands over the right value, or the system searches prior calls for the same argument. That breaks as soon as the preference never appears in the target function, or never appears at all. In those cases, retrieving history does not solve the missing parameter.

The paper’s move is to treat preference as latent and infer it across sessions. MPT turns SGD, DuRecDial 2.0, and HomeBench into 4,695 instances over 459 multi-session histories, then separates Recall, Induction, and Transfer according to how much evidence the history exposes. PRefine keeps a textual preference hypothesis in test-time memory and runs a generate–verify–refine loop; only hypotheses that fit the accumulated behavioral record survive.

Across five LLMs, the macro-average O-F1 on context-guided queries rises from 58.17 with Full-History Prompting to 73.57 with PRefine. On context-free queries, it rises from 35.29 to 60.55. The harder Transfer setting is where the gap matters most: macro-average O-F1 goes from 17.51 to 32.31, and PRefine is the only method that beats Full-History Prompting there. The ablation is clean: generation alone does little, and unverified refinement hurts; the verifier is doing the work.

This is a real step toward agent memory that abstracts behavior instead of archiving it. The cost is not trivial, but PRefine’s memory construction uses 8,855.57 tokens per session, below Mem0’s 9,424.11 and far below A-MEM’s 27,276.66. The boundary is also clear: the benchmark is schema-bounded, and Transfer under high evidence interference still remains the hardest case.

方法Method

core idea
PRefine 把 latent preference 当成可修订的文本假设。每轮先根据上一版 memory、当前 session 和已执行 tool calls 生成候选偏好，再用 verifier 检查它是否被累计历史支持、是否足够抽象、是否可直接行动、以及是否跨 session 一致。通过验证的假设才写回 memory；否则按反馈再改，最多 5 轮。
PRefine treats latent preference as a revisable text hypothesis. At each step, it generates a candidate from the previous memory, the current session, and executed tool calls, then a verifier checks whether the hypothesis is supported by the accumulated history, abstract enough, actionable, and temporally consistent. Only verified hypotheses are written back to memory; otherwise the candidate is refined again, for up to 5 rounds.

长程 LLM agent 的难点不是“有没有奖励”，而是一次成功只给终点一个稀疏分数，整条轨迹都被同样广播，动作之间真正该记功的关系被抹平。已有方法多从 rollout 侧补细粒度信号，但仍把 verifier 当成一个标量，丢掉了它内部已经写好的任务结构。

VICT 的关键动作，是把 verifier 里可执行或有证据支持的原子检查显式暴露出来，再用依赖有效的 proof edges 把这些原子回溯到动作。训练时只沿这些边重新分配 group-relative advantage；终局奖励不变，但只有证据完整且不含糊时才传信用。它不需要 learned critic、process labels、branch rollouts，也不需要推理时再访问 verifier。

摘要只报告它在 ALFWorld 和 WebShop 上“显著优于”只用终局结果训练的方法，并且能和近期细粒度 credit 方法竞争；同时，消融实验排除了 dense atom rewards、final-commit credit、temporal proximity 和 sparsity 这几种简单解释。没有给出具体分数、样本量或开销，所以只能判断方向性结论成立。

The problem is not whether long-horizon LLM agents get a reward; it is that a single terminal success signal gets smeared across an entire trajectory, so the actions that actually made the verifier happy stay indistinguishable. Prior fine-grained credit methods mostly try to infer importance from the rollout side, but they still treat the verifier as a scalar and throw away the task structure already inside it.

VICT’s move is to expose executable or evidence-backed atoms from the terminal verifier, then trace those atoms back to actions through dependency-valid proof edges. During training, it redistributes group-relative advantage only along those edges. The terminal reward stays intact, but credit is withheld when evidence is incomplete or ambiguous. It needs no learned critic, process labels, branch rollouts, or inference-time verifier access.

In the abstract, the empirical claim is directional rather than quantified: on ALFWorld and WebShop, VICT beats outcome-only training by a substantial margin and is competitive with recent fine-grained credit methods. The authors also say ablations rule out dense atom rewards, final-commit credit, temporal proximity, and sparsity as sufficient explanations. No exact scores, compute, or scale are given in the abstract.

The useful shift here is conceptual: credit assignment becomes verifier tracing, not rollout guessing. That is directly relevant to agentic RL on tool-use and other verifiable tasks. The catch is that the paper only shows an abstract here, so it is unclear how the method behaves when the verifier is weak, the evidence is partial, or the task is not naturally decomposable into dependency edges.

多智能体 agent 出错后，单点归因只会告诉你“某条消息可疑”，却分不清是两条消息必须一起改，还是改任一条都行。对调试来说，这两种 failure 该走的搜索路径完全不同。

作者把目标改成 MRFR：恢复所有“最小且能让 replay 成功”的事件集。GCJR 先沿依赖图做 backward slice，再只保留跨 agent、互不可达、且在下游汇合的单点/成对候选，最后用 paired clean counterparts 做 counterfactual replay，并用最小性过滤掉非最小解。

在 120-DAG 控制集的 90 个 in-scope case 上，GCJR 的 Family Exact Match 是 1.000，平均 replay 从 56.3 降到 25.3，少 55.1%。在 24 个四 agent 的 DualSolve-MAS pilot 里，它同样做到 1.000 FEM，把平均 model calls 从 21.0 降到 10.0，少 52.4%；单事件 replay 会漏掉联合必要修复。

这篇工作的价值不是又一个责任分数，而是把“可修复的最小交互集合”直接列出来，能同时表达 AND 和 OR 两类故障。不过它只在声明的 graph 域内精确，漏掉 10% 边时 macro FEM 会掉到 0.552；它也只搜到单点和成对修复，并且本身不生成修复文本。

When a multi-agent LLM system fails, pointwise attribution is too coarse: it can flag a message or step, but it cannot tell whether two messages must both be fixed or whether either one alone would suffice. That distinction changes the debugging search immediately.

The paper’s move is to replace scalar blame with MRFR, the family of inclusion-minimal event sets that make counterfactual replay succeed. GCJR gets there in three steps: it backward-slices the failure sink, keeps only graph-feasible singleton and cross-agent pair candidates that meet at a downstream join, and then replays each candidate against paired clean counterparts. Successful sets are kept only if all strict subsets fail, so the output is an antichain rather than a ranking.

On the 120-DAG Controlled-DAG benchmark, 90 in-scope cases are recoverable. GCJR reaches 1.000 Family Exact Match, the same as exhaustive search, but cuts mean replay calls from 56.3 to 25.3, a 55.1% reduction. On a 24-case four-agent DualSolve-MAS pilot built around local Qwen2.5-1.5B-Instruct, it again gets 1.000 FEM and reduces mean model calls from 21.0 to 10.0, or 52.4%. Single-event replay misses jointly necessary repairs, and Exact Shapley top-2 gets 1.000 first-hit success but only 0.333 macro FEM because it confuses OR cases with a non-minimal pair.

The main value is conceptual as much as algorithmic: the method preserves the AND/OR distinction that a ranking erases. The catch is that it only works within the assumed dependency graph, and hiding 10% of edges drops macro FEM to 0.552. It is also limited to singleton and pair repairs, and it diagnoses by replay rather than generating fixes.

现有 tool-use agent 训练卡在三个缺口：真实环境没有预定义任务和 verifier，没有可信 simulator，而且反复 on-policy 交互太贵，往往只能靠过滤后的少量轨迹，信息损失很大。

AgentBrew 的关键动作是把一批原始轨迹直接变成监督信号。先用 retrospective task inference 按轨迹的实际结果重建对齐 instruction，再用 PMI-Based credit assignment 把轨迹对该 instruction 的总信息量拆成逐动作的加性 credit，用这些 credit 加权 policy objective，放大有信息的动作，压低无效动作。

摘要给出的实证只覆盖三个真实 MCP 应用：GitHub、Notion、PostgreSQL。它报告 AgentBrew 让 Qwen3-32B 平均提升 $+8.7$ Acc / $+9.7$ Score；同条件下 Qwen3-235B 只到 $+2.3$ / $+4.4$，而 rejection sampling 为 $+5.9$ / $+10.3$。

这说明细粒度 offline learning 确实能从原始轨迹里挖出过滤法会丢掉的监督。但摘要里看不到任务定义、credit 公式、轨迹噪声水平和消融，所以还不能判断它靠的是稳定方法还是这三个应用上的偶然收益。

Tool-use agents are hard to train in real deployments because the environment rarely comes with task labels, verifiers, or a faithful simulator, and large-scale online interaction is too expensive. The usual fallback is to filter trajectories and learn from the survivors, but that throws away most of the signal in raw interaction logs.

AgentBrew’s move is to turn one noisy batch of trajectories into training signal without on-policy rollouts. It reconstructs an aligned instruction for each trajectory from the observed outcome, then uses PMI-based credit assignment to decompose the trajectory’s total information about that inferred instruction into additive per-action credits. Those credits weight the policy objective, so informative actions get reinforced and ineffective ones get downweighted.

The abstract reports results on three real MCP applications: GitHub, Notion, and PostgreSQL. On average, AgentBrew improves Qwen3-32B by $+8.7$ Acc / $+9.7$ Score. It also beats Qwen3-235B, which reaches only $+2.3$ / $+4.4$, and rejection sampling, which gets $+5.9$ / $+10.3$.

The practical claim is strong: offline learning can recover supervision from raw trajectories that filtering-based methods would discard. But with only the abstract, the hard questions stay open: how robust the retrospective task inference is, whether PMI credits are stable under noisy or partially observed actions, and whether the gain holds beyond these three MCP settings.

Current agentic forecasting collects evidence, writes a prose synthesis, and then appends a probability whose derivation is opaque. Think&Search and deep-research agents can improve accuracy, but the update path from evidence to forecast still collapses into narrative aggregation, which is hard to calibrate and even harder to audit.

AuditForecast’s move is to force an explicit decomposition.
