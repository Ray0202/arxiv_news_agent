ST-Lite: Training-Free KV Cache Compression with Spatio-Trajectory Guidance for Long-Horizon GUI Agents

三招保住 GUI 长程轨迹里的关键 KV，20% 缓存追平 Full Cache

ST-Lite preserves GUI-critical KV pairs with three structure-aware rules and matches Full Cache at 20% budget.

Bowen Zhou, Zhou Xu, Wanli Li, Jingyu Xiao 等 6 人 +2 more

现有 KV cache 压缩多按通用语言负载设计，碰到 GUI agent 就漏关键记忆：跨帧画面冗余高、UI 元素极小、各层 attention 稀疏还很平。结果是在标准 20% 预算下，方法最多只保住了 39% 的 oracle 重要 KV 对。

ST-Lite 的做法是按这三种结构性偏差逐个下手。TSG 根据轨迹过滤重复历史帧，CSS 优先保留细粒度元素边界，平坦的逐层预算避免把容量错分给少数层；整个方案是 training-free，目标是在不训练新压缩器的前提下更像 GUI 工作负载本身。

摘要里给出的实验结论是：在 7 个 GUI benchmark 和 2 个 backbone 上、10%-$40%$ 压缩窗口内，ST-Lite 都优于现有压缩基线；在主 backbone 的 20% 预算下，它能匹配或超过 Full Cache 任务准确率，并在五倍压缩时带来最高 2.35x 解码加速。

这篇工作的价值很直接：它把 GUI agent 的 KV 压缩从“通用语言模型的缓存裁剪”拉回到交互轨迹和界面几何结构上。局限也清楚，现阶段只看摘要，细节上还看不到各组件消融、不同 UI 分布下的稳健性，以及 2.35x 加速对应的绝对延迟和内存配置。

Generic KV cache compression misses what GUI agents actually need: repeated frames, tiny UI elements, and nearly uniform sparsity across layers. The paper says that at a standard 20% budget, existing schemes keep as few as 39% of the oracle-important KV pairs.

ST-Lite fixes those three failure modes directly. Trajectory-aware Semantic Gating drops redundant historical frames, Component-centric Spatial Saliency keeps fine-grained element boundaries, and a flat per-layer budget avoids hierarchical misallocation. The whole method is training-free, so the compression policy is tailored to GUI interaction traces rather than learned from scratch.

The abstract reports results on seven GUI benchmarks and two backbones in the 10%-40% compression range. ST-Lite beats all listed compression baselines throughout that window; on the primary backbone at 20% budget, it matches or exceeds Full Cache task accuracy, and at fivefold compression it reaches up to 2.35x decoding speedup.

The main takeaway is that GUI cache compression needs spatial and temporal structure, not just generic token salience. What remains unclear from the abstract is how much each module contributes, how the method behaves across different UI distributions, and what absolute latency and memory numbers sit behind the reported speedup.

Eluna: An Agentic LLM System for Automating Warehouse Operations with Reasoning and Task Execution

DAG 披露+蒸馏让 32B 追平 355B 教师

Graph-guided SOP execution plus asymmetric episodic distillation lets a 32B student match a 355B teacher.

仓库 SOP 不是难在单点推理，而是难在多系统、强时限、还必须按流程走。现有 LLM agent 往往靠松散 prompt，遇到完整 SOP 就被上下文塞满，还是会偏离既定路径；手工执行又慢又错。

关键动作是把 SOP 编成 DAG $G=(V,E)$，只暴露当前可达子图。主 agent 负责遍历，独立节点交给并行 sub-agents；每个 sub-agent 只拿单节点规格、persistent code interpreter 和 MCP 工具。训练上再做 asymmetric episodic distillation：先用 episodic learning 修正 teacher 轨迹，再把筛过的 turn-level 轨迹 LoRA 到不带 memory 的 student。

在 13-task benchmark 上，Eluna-G 平均比 GLM-4.5-Air 提升 $6.5\%$，Eluna-Q 提升 $6.0\%$，并基本追平 teacher 的 $6.1\%$。在 robotic conveyance 上，训练后模型把 observation binary correctness 提升到 $49\%$ 以上、root-cause binary 提升到 $73\%$ 以上，actions 的 exact match 提升到 $165\%$ 以上，median latency 还比 GLM-4.7 降了 $54.3\%$/$54.8\%$。ticket processing 上，Eluna-G-XL（355B）的 estimated correctness 为 $94.4\%$，precision $96.7\%$，recall $99.2\%$，F1 $98.0\%$。

这说明流程约束不是靠更大的模型就能补上，真正有效的是把 SOP 结构和训练信号一起写进系统。它的短板也清楚：跨更不同的 operational environment 还没验证；teacher、反复生成轨迹和标注都贵；ticket 结果还是抽样专家复核，不是全量真值。

Warehouse SOP execution is brittle because the task is not just reasoning; it is reasoning under strict procedure, cross-system dependencies, and latency pressure. Existing LLM agents rely on loose prompts, so a full SOP still overwhelms context and agents drift off the prescribed path. Manual execution is slower and more error-prone still.

The trick is to encode each SOP as a DAG $G=(V,E)$ and reveal only the reachable subgraph. A main agent traverses the graph, while independent nodes are evaluated by parallel sub-agents; each sub-agent gets only the node specification, a persistent code interpreter, and MCP tools. Training adds asymmetric episodic distillation: episodic learning first repairs a teacher's trajectories, then a LoRA student is fine-tuned on corrected turn-level trajectories with memory removed.

On the 13-task benchmark, Eluna-G averages +6.5% over GLM-4.5-Air and Eluna-Q averages +6.0%, essentially matching the teacher's +6.1%. On robotic conveyance, the trained models push observation binary correctness above +49%, root-cause binary correctness above +73%, and action exact match above +165%, while median latency drops 54.3%/54.8% relative to GLM-4.7. On ticket processing, Eluna-G-XL (355B) reaches 94.4% estimated correctness, 96.7% precision, 99.2% recall, and 98.0% F1.

The paper's main claim is that procedural reliability comes from coupling graph structure with training, not from scaling the base model. The limits are practical: transfer to very different operating environments is still untested, the teacher-and-distillation pipeline needs compute and labels, and the ticket-processing score is based on sampled expert review rather than exhaustive ground truth.

Existing mobile-agent benchmarks miss the hard part from opposite directions. GUI-centric suites watch screen clicks but ignore background tool use and runtime exceptions. Static function-calling suites check offline string or JSON matches, which means they never see how a planner reacts to permission blocks, state mutation, or a bad call order.

The trick is to turn mobile planning into a closed-loop function-calling problem. MobilePA-Bench lets a central planner choose an action from $q$, $\mathcal{H}_t$, and $\mathcal{A}_t$, then executes it in a stateful sandbox that returns structured feedback $f_t$. The action space is split into Direct Mobile Tools, Sub-agent Entry, Memory Tools, and Skill Loading, and skill loaders dynamically expand the candidate set. Evaluation is also bucketed by completion semantics: Tool Call, State Change, or Agent Behavior.

They run 13 models on $1,705$ tasks, $13$ domains, and $212$ tools. Claude-Opus-5 leads overall at $75.52\%$, with $83.85\%$ on Basic Tool Use, $77.53\%$ on Sub-agent Collaboration, $64.63\%$ on Memory Usage, and $78.00\%$ on Skill Usage. Qwen3.6-27B is also stable under repeat runs, with overall score ranging only from $57.22\%$ to $57.63\%$.

The main signal is not that one model wins, but that no model combines routing, memory, and recovery reliably once the environment starts pushing back. That makes MobilePA-Bench a useful diagnostic for agent design and RL-style training, but not a proof of deployable mobile autonomy. The catch is that the headline score uses a $50/10/20/20$ weighting, so basic tool execution dominates the final number and can hide brittle delegation and personalization.

When an LLM agent has to refine candidates under a tight evaluation budget, standard MCTS spends too much on the wrong branches: exploration bonuses dominate at low visit counts, weak siblings get expanded before strong chains can deepen, and branching ignores node quality.

ExTS makes expansion itself a value-of-information decision. It combines discriminative reward shaping to spread out narrow score distributions, a stochastic virtual child that estimates the payoff of creating a new branch from the parent’s reward history, and quality-conditioned branching so expansion happens only when the score justifies the budget cost.

The abstract claims competitive or better results on prompt optimization, code generation, molecular structure elucidation, and agentic workflow optimization versus task-specific tree-search baselines, with a $+5.5\%$ average relative gain under one fixed configuration. That is the only hard number given here, so the scale of the gain on each task, and which component matters most, remains unclear.

The useful idea is not another search heuristic, but a budgeting rule for agentic search that tries to spend expansion where it is informative. That is relevant to agent work; the time-series connection is thin. With abstract-only evidence, though, the robustness story is still open.

Multi-turn tool use fails less from malformed calls than from state drift. Direct function-calling and ReAct-style policies fold state tracking and action selection into one autoregressive pass, so the next call can overwrite older constraints, reuse stale values, or contradict earlier turns. The paper names this state-action competition.

OODA-Tool breaks one turn into Observe, Orient, Decide, and Act, with a central controller checking each handoff. Observe reconstructs a provenance-aware task state; Orient decides whether the agent should execute, ask for clarification, recover, or stop; Decide emits only an admissible action structure; Act compiles that structure into a schema-valid tool call or approved natural-language reply. Three LoRA variants, Joint, Shared, and Specialized, isolate one-pass generation, stage-wise inference, and stage-specific adaptation.

On ToolDial's 11,111 multi-turn sessions, Qwen3 backbones from 0.6B to 14B all gain in Task Success. Specialized OODA beats Direct-LoRA by 6.86, 6.79, 6.99, 5.94, and 4.48 points at 0.6B, 1.7B, 4B, 8B, and 14B. Figure 3 shows the biggest gains on long histories, missing-information turns, state changes, and deeper dependencies, while Figure 4 shows the largest ablations from removing Orient or the Decide–Act split. At 1.7B, Specialized OODA costs $2.36\times$ normalized latency.

The practical message is that typed state and execution gating help when success depends on carrying context forward, but they do not solve parallel call expansion. Gains are smaller on BFCL Multi-turn and on ToolDial's parallel-call cases. The typed-state bottleneck suggests most, not all, relevant context survives compression, so Direct-LoRA still wins when one-pass latency is the main constraint.

长程任务里，历史越积越多，状态反而越模糊；技能调用也更容易被整段历史带偏，RSI 因而很难落地。这里真正卡住的不是“会不会记”，而是“记什么、何时改、改哪一层”。

Recuris 的做法是把记忆拆成 Working Memory 和 Experiential Memory：前者只追踪当前进度并约束技能选择，后者保存可复用经验。执行过程本身会产出结构化证据，用来把失败定位到具体记忆组件；再由固定的 Meta-Agent 把这些证据转成局部、带验证门控的 Skill Memory 更新，形成有边界的递归记忆演化回路。

摘要称，在四个长程基准和十个模型上，它在 37 个已完成的模型-基准组合里赢了 35 个。tau-bench 上，对 GPT-5.6 Sol 提升 $17.8$ 点，对 Claude Opus 5 提升 $15.6$ 点，把 Opus 5 推到 $87.9 ext{%}$；在 SkillFlow 上，对 Qwen3.6-27B/35B 分别提升 $16.6$ 和 $13.5$ 点。最长任务上的优势扩大到 $32.2$ 点，共同的长程失败最多下降 $80 ext{%}$。

这篇工作的价值在于，它把“记忆”从静态存储改成了可被执行证据驱动的更新机制，比较贴近长程 agent 真正需要的闭环。限制也很明显：目前只有摘要，验证门控、失败归因和各记忆组件的消融都看不到；而且这些提升是否稳定依赖于基准和模型组合，摘要还不能说明。

Long-horizon agents do not usually fail because they lack experience; they fail because the history gets so large that task state blurs and skill invocation drifts away from current needs. The hard part is not storing more, but deciding what to remember, when to update it, and which memory layer should change.

Recuris splits memory into Working Memory and Experiential Memory. Working Memory tracks progress and steers skill selection from Experiential Memory, so retrieval is grounded in the current task state rather than the full transcript. Execution then produces structured evidence that localizes failures to specific memory components, and a fixed Meta-Agent turns that evidence into localized, validation-gated Skill Memory updates, creating a bounded recursive memory-evolution loop.

The abstract reports results on four long-horizon benchmarks and ten models. Recuris improves 35 of the 37 completed model-benchmark pairs. On tau-bench it adds $17.8$ points to GPT-5.6 Sol and $15.6$ to Claude Opus 5, bringing Opus 5 to $87.9 ext{%}$; on SkillFlow it adds $16.6$ and $13.5$ points to Qwen3.6-27B and Qwen3.6-35B. The gap grows with interaction length, reaching $32.2$ points on the longest tasks, and common long-horizon failures drop by up to $80 ext{%}$.

The core contribution is turning memory into an updateable control loop, not a passive log. That is plausibly the right abstraction for RSI-like agent systems. But the evidence here is still abstract-level: the gating rule, failure attribution, and component ablations are not visible, and the robustness of the gains across benchmarks and model families remains untested from the text alone.
