现有论文检索多依赖预设流程或结构化交互协议，遇到条件分支复杂的查询时，检索器往往被固定脚本绑住，难以按上下文动态决定下一步动作。结果是该找的时候不敢找，该扩展的时候不会扩展，召回和相关性都容易掉。

PaperScout 把论文搜索改写成 sequential decision-making process。核心动作是让 agent 根据累计检索上下文，动态决定是否、何时、以及如何调用 search 和 expand tools；配套的 PSPO 则把优化粒度对齐到 sequence-level interactions，而不是 token-level，让训练信号直接对应一整轮 agent--environment 交互，减少 noisy credit assignment 和不稳定更新。

摘要只给出方向性结论：在 synthetic 和 real-world benchmarks 上，PaperScout 相比强 structured retrieval 和 RL baselines，在 recall 和 relevance 上都更好。没有看到具体分数、提升幅度或消融，因此只能确认它在这两类基准上都赢了，不能判断优势有多大，也不能拆出是搜索策略还是 PSPO 贡献更大。

这篇工作对 agent 和信息检索交界面有直接意义：它不是再堆一个检索管线，而是把搜索本身当成可学习的多步决策过程来训。短板也很明显，摘要没有交代 benchmark 名称、任务设定、工具接口和训练规模；如果正文里没有更细的对照，结论很难外推到真实论文库检索以外的场景。

Most paper search systems are still wired around preset workflows or structured interaction protocols, and that breaks down when queries need conditional, back-and-forth decisions. The practical failure mode is simple: the retriever cannot decide dynamically when to search, when to expand, and when to stop, so recall and relevance suffer on harder queries.

PaperScout changes paper search into a sequential decision-making problem. The agent uses accumulated retrieval context to decide whether, when, and how to invoke search and expand tools. Training uses Proximal Sequence Policy Optimization, which moves the optimization target from token-level updates to sequence-level agent--environment interactions, aiming to reduce noisy credit assignment and unstable learning.

The abstract claims gains on both synthetic and real-world benchmarks against strong structured retrieval and RL baselines, with improvements in both recall and relevance. But it gives no benchmark names, no scores, and no ablations, so the size of the gain and the source of the gain remain unknown.

For agent research, the interesting part is the shift from fixed retrieval pipelines to learned search behavior under sequence-level optimization. The catch is also clear: with only the abstract, there is no way to judge how hard the benchmarks are, whether the tool setup is realistic, or whether PSPO generalizes beyond this paper-search setting.

以前的 LLM evolution 不是模型不够强，而是关键搜索决策被写死：选哪些父代、何时本地验证、何时回写知识，都由 fixed heuristics 控制，agent 只是在补全候选。多智能体系统也常靠人工分工和固定通信，到了开放式发现时就显得僵硬。

CORAL 的核心动作是把 retrieve/propose/evaluate/update 尽量交给 agent，再用共享 persistent memory 把多个长期运行的 agent 连起来。记忆分成 attempts、notes、skills 三类，agent 在 isolated worktrees 中异步探索；heartbeat 则定期触发反思、整理和改道，防止搜索陷入局部微调。

在 6 个数学任务、5 个 systems 任务和两个 stress test 上，CORAL 在 11 个任务里都拿到最优 final score，并在 8 个任务上刷新 SOTA。和 fixed evolutionary search 比，它的 improvement rate 高出 3–10 倍，通常只用 5–20 次 evaluation，而基线要 60–100 次。Kernel Engineering 上，4-agent 把 1,363 cycles 压到 1,103；Polyominoes packing 的 web-enabled 结果到 89.4%，超过此前 87%。

这说明 autonomy 不是给搜索器再包一层 LLM，而是让 LLM 部分充当搜索器本身。论文也显示，收益最强的是能本地执行、还能沉淀知识的任务；像 Prism 这类隐藏/随机评测，本地验证几乎没空间。局限是系统更复杂，而且 multi-agent 协作的收益并不均匀。

The bottleneck is not raw model quality. It is that most evolutionary systems hard-code the search policy: parent choice, intermediate verification, and what gets written back to memory are fixed by heuristics, while the LLM only mutates a candidate. Multi-agent systems often add human-designed roles and communication graphs, which is fine for bounded workflows but brittle for open-ended discovery.

CORAL moves those decisions into the agents. Each agent runs in an isolated worktree, reads and writes a shared persistent memory, and cycles through retrieve/propose/evaluate/update asynchronously. Memory is split into attempts, notes, and skills, and heartbeat events periodically force reflection, consolidation, and redirection so search does not collapse into local edits.

On 6 math tasks, 5 systems tasks, and two stress tests, CORAL gets the best final score on all 11 tasks and new SOTA on 8. Against fixed evolutionary search, its improvement rate is 3–10x higher and it usually reaches the final score in 5–20 evaluations instead of 60–100. On Anthropic's kernel engineering task, 4 co-evolving agents reduce the score from 1,363 to 1,103 cycles; on web-enabled Polyominoes, CORAL reaches 89.4%, above a prior best of 87%.

The real claim is that autonomy plus shared memory can replace much of the hand-designed outer loop. The payoff is strongest when agents can run local tests and distill reusable knowledge; on hidden or randomised grading, like Prism, local verification has little room to help. The caveat is system complexity, and the multi-agent gain is not uniform across tasks.

方法Method

core idea

Open-ended discovery is cast as a four-step loop: Retrieve, Propose, Evaluate, Update. A task is described by $x$ and an evaluator $E$; $E(x,y)$ returns a score $s$ and feedback $f$. CORAL lets agents decide when to retrieve, when to test locally, when to call $E$, and what to write into shared persistent memory $\mathcal{M}$. Heartbeat events trigger reflection, consolidation, and redirection when progress stalls.

data

RL post-training often treats all parameters as if they should follow a fixed schedule, but this abstract says that assumption is wrong. Capacity parameters accumulate monotonically across stages, while regularization parameters oscillate with training dynamics. LLMZero’s move is to search over training trajectories instead of tuning one knob at a time. 长程 agent 和多轮对话不是没记住，而是上下文窗先满了。写入时必须先删，删错一个登录 token、路径或实体，下一步就会失败。现有 retrieval 要等 query，recency/decay 只看新近，LLM 压缩又会改写 exact state，都不适合这个场景。

LRE 的动作是把 eviction 变成 query-blind relevance prediction。它只用前缀 $u_{\le i}$ 的廉价特征给每个历史单元打分 $p_i$，再在预算 $B$ 下按 $p_i/c_i$ 做 knapsack；最近窗口 $R_k$ 原样保留，输出只做 verbatim extraction。训练器是 $L2$ 正则 logistic regression，监督可来自人工 gold，也可来自系统后续 reuse 行为。

在 AppWorld 上，$2048$-token 预算下，LRE 的总体 Acc 是 $41.1\%$，接近不压缩的 $44.0\%$，但最坏峰值 prompt 降了约 $52\%$，compressor calls 也为 $0$；Easy 任务上它到 $73.7\%$，高于 $57.9\%$。在 LoCoMo 上，它在读入 $68\%$ 更少 tokens 时拿到最好 budgeted answer quality；在 LongMemEvalS 和 LoCoMo 的 relevance ranking 里，LRE-supervised 的 Macro-AUC 到 $0.708$ 和 $0.829$，自监督标签还能保住监督版约 $95\%$ 的信号。

这说明 eviction 里最值钱的不是摘要，而是把未来会用到的 exact state 留住。它也有硬边界：如果后续依赖在轨迹里弱或没显现，模型再便宜也可能删错；作者还没测 multimodal、协作多智能体或快速变化外部状态。

Long-horizon agents and multi-session assistants do not fail because they cannot store history; they fail because the context window fills before the system knows what will matter later. Evicting the wrong login token, path, or entity makes the next step fail even when the history was accurate. Retrieval waits for a query, recency and decay only reward freshness, and LLM compression can rewrite the exact state the task needs.

LRE turns eviction into query-blind relevance prediction. For each unit, it uses cheap features from the prefix $u_{\le i}$ to score relevance $p_i$, then solves a knapsack-style selection under budget $B$ by ranking units by $p_i/c_i$. The recent window $R_k$ is always kept, and the retained history is emitted verbatim rather than summarized. The scorer is $L2$-regularized logistic regression, and supervision can come from human gold or from the system's own later reuse behavior.

On AppWorld with a $2048$-token budget, LRE reaches $41.1\%$ accuracy versus $44.0\%$ for full history, while cutting worst-case peak prompt size by about $52\%$ and making $0$ compressor calls; on Easy tasks it gets $73.7\%$ versus $57.9\%$. On LoCoMo it gets the best budgeted answer quality while reading $68\%$ fewer tokens. For relevance ranking, LRE-supervised reaches Macro-AUC of $0.708$ on LongMemEvalS and $0.829$ on LoCoMo, and the self-supervised label keeps about $95\%$ of the supervised signal.

The paper's claim is narrower than a generic memory story: cheap learned relevance is enough when exact state matters, but only if the future dependency is already latent in the observed trajectory. That makes it appealing for deployed agent memory and brittle when later dependencies are weakly expressed. The authors do not test multimodal memory, collaborative multi-agent systems, or rapidly changing external state.

Terminal agent 训练卡在两头：从零合成的环境很快被前沿模型做穿，reward 信号变薄；而 on-policy co-evolution 又把难度绑在当前模型的失误上，模型越强，可用失败样本越少。结果是环境构造成本还在，学习信号却断流。

关键动作是把难度从“某个模型会不会失败”改写成可沿 lineage 递增的 off-policy 量。作者从 multi-turn 学习目标推导出 $D_{\mathcal{T}}(\xi)$，把难度拆成 scenario novelty、skill rarity 和 execution length 三个维度，再用 loop-engineered multi-agent harness 逐代改写环境；EL Scheduler 则按 generation 顺序放行更难的样本，避免一上来就全是学不会的环境。

Hy4 preview、Claude Opus 5 和 GPT-5.6 Sol 的 rollout 评估都显示，evolved environments 更难。Qwen3.6-27B 和 Qwen3.6-35B-A3B 在 Terminal-Bench 2.1 上的峰值分别到 71.5% 和 64.9%，高于 co-evolution 的 62.9% 和 55.1%；摘要还报出 14.4 和 18.0 个百分点的提升。Table 1 里 length 方向单步就带来 $-7.1$ pp pass rate 和 $+9.4$ turns，而 scenario/skill 更偏向拉长交互。

这说明环境 scaling 不必依赖目标 agent 的 rollout 才能持续供信号：把环境本身做成可验证的 difficulty lineage，确实能把长程 RL 往前推。它的短板也清楚：强依赖 seed environment 质量、Oracle/verification 设计和人工复核，且只在 terminal agents 上验证，迁到 SWE 或 Computer-Use 还没证实。

Terminal-agent training gets squeezed from both sides: environments synthesized from scratch are now too easy for frontier models, so the reward signal fades fast; on-policy co-evolution also ties difficulty to the current policy’s failures, so as the model improves, usable failures become rare. Environment construction still costs money, but the learning signal dries up.

The move is to define difficulty off-policy and let it grow generation by generation. The paper derives $D_{\mathcal{T}}(\xi)$ from the multi-turn learning objective, splitting difficulty into scenario novelty, skill rarity, and execution length. A loop-engineered multi-agent harness edits an existing environment along one of those axes, and the EL Scheduler releases harder generations in order so training does not jump straight to unsolved cases.

Rollout checks with Hy4 preview, Claude Opus 5, and GPT-5.6 Sol show that the evolved environments are harder across models. On Terminal-Bench 2.1, Qwen3.6-27B peaks at 71.5% and Qwen3.6-35B-A3B at 64.9%, versus 62.9% and 55.1% for co-evolution. The abstract also reports 14.4- and 18.0-point gains. Table 1 shows the direction control working as intended: a length edit drops pass rate by $7.1$ pp in one step and adds $9.4$ turns, while scenario and skill edits mainly stretch the interaction.

The practical point is that environment scaling does not have to wait for target-agent rollouts to keep producing curriculum signal. The weak spots are equally practical: it leans on seed quality, Oracle and verifier design, and human review, and the validation is still confined to terminal agents, not SWE or Computer-Use settings.
