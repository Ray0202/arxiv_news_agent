Can Agent Memory Systems Track Evolving State?

StateMem 显式追踪状态更新，StateMemBench 上提 $1.8\times$。

StateMem explicitly tracks supersession and dependencies, lifting StateMemBench current-state accuracy $1.8\times$ over the strongest same-backbone baseline.

现有 agent memory 多在追 recall：把相关片段捞出来，却不管后续 session 已经把它覆盖了。于是会出现 state drift，答案里明明带着旧值，模型却按旧值行动。作者把缺口从“找不找得到”拆成“当前到底谁生效”，把 state tracking 定为与 recall 不同的能力。

关键动作是把记忆改成 state-first。StateMemBench 用 symbolic event program 生成多 session 场景，把 facts、rules 和 derived quantities 的 supersession 与依赖写死，再用 closed-pool 评分区分 drift、off-pool 和其他错误。StateMem 先把每轮对话解析成 state units，再在更新时显式标记 superseded，并沿依赖图 $G=(U,E)$ 做 deterministic recheck；回答时只对活跃状态重算。

在 $234$ 个场景上，长上下文、retrieval 和现有 memory baseline 都被这些陷阱压住。DeepSeek-V4-Flash 上，StateMem 准确率 $0.363$，高于最强同骨干基线 $0.205$；Qwen-3.5-9B 上是 $0.233$ 对 $0.149$。作为 wrapper，它在 $6$ 个 backend 上还能带来 $+31.7$ 到 $+66.6$ 个点，其中 $+15.0$ 到 $+31.7$ 个点来自状态结构本身。

这说明 state tracking 不是 recall 的副产物，而是可以单独设计、单独评测的能力；显式状态结构确实有用，但前提是答题模型不能太弱。它的短板也明显：salience 仍然很吃力，而且 StateMemBench 的冲突是人为构造、closed-pool 的，测得更像受控状态维护，不是开放世界记忆。

Most agent memory work chases recall: can the system surface the right snippet? That misses state drift, where the relevant fact is present but the agent acts on an outdated value after later revisions. The paper argues the real gap is not retrieval but maintaining the currently operative state across sessions.

The trick is to make state a first-class object. StateMemBench generates multi-session scenarios from symbolic event programs, with explicit supersession and dependency structure, then scores closed-pool answers so drift is separated from generic errors. StateMem parses each turn into state units, marks units as superseded, propagates invalidation over a dependency graph $G=(U,E)$, and asks the model to recompute only from the surviving state.

On $234$ scenarios, existing memory, retrieval, and long-context baselines struggle. StateMem reaches $0.363$ on DeepSeek-V4-Flash, up from $0.205$ for the strongest same-backbone baseline, and $0.233$ on Qwen-3.5-9B versus $0.149$ for the strongest memory system. As a wrapper, the same state tracing adds $31.7$ to $66.6$ points over $6$ backends on StateMemBench, with $15.0$ to $31.7$ points attributed to structure rather than extra text.

The main takeaway is that state tracking is a separable capability, not a side effect of better recall. But the wins are uneven: salience remains weak on the Qwen backbone, and the wrapper can beat the full persistent system when the transcript still fits in context. The benchmark also uses explicit, closed-pool conflicts, so it measures controlled state maintenance more cleanly than messy real-world memory.

方法Method

core idea
StateMem 把多轮记忆表示成 state units，每个 unit 记录 $id$、content、priority、source 和 $deps$。输入阶段每轮一次 LLM 抽取，更新阶段先做 supersession，再沿依赖图 $G=(U,E)$ 做 deterministic recheck；测试时把活跃状态渲染成结构块 $\mathcal{S}$，再用一轮 LLM 只对当前有效状态重算答案。这样把“谁被覆盖了、谁还有效”从生成模型里拆开。
StateMem represents multi-turn memory as state units, each with $id$, content, priority, source, and $deps$. Ingestion uses one LLM call per turn to extract units, update applies supersession and then runs a deterministic recheck over the dependency graph $G=(U,E)$; test time renders the active state as a structured block $\mathcal{S}$ and uses one more LLM call to recompute the answer from current state only. The point is to separate “what was overwritten” from “what is still in force.”
architecture
TurnEncoder -> StateStore -> Rechecker on $G=(U,E)$ -> render $\mathcal{S}$ -> answer call; $u=(id,content,priority,source,deps)$, $priority\in\{hard,soft\}$, $deps\in\{derived\_from,coupled\_with\}$
data
StateMemBench: $234$ multi-session scenarios; Set A $190$ single-probe scenarios, $18$ sessions each ($\sim165$ turns, $\sim3$k tokens); Set B $44$ fused scenarios, $\sim38$ sessions each ($\sim599$ turns, $\sim7$-$15$k tokens). Domains: research, shopping, personal finance. Also evaluated on LongMemEval ($n=500$, $k=20$) and LoCoMo ($n=1,985$).

LifeMem reduces static-profile group compression by adding longitudinal life-event memory and agent-specific parametric memory.

静态 profile 的 LLM agents 往往把人口标签当成个体本质，结果是组内回答被压扁、组间差异被放大，和真实人群的多样性不一致。问题不只在 prompt 写得不够细，还在于经验只能靠 prompt-only memory 短暂拼接，难以持续累积。

关键动作是把记忆拆成两层：一层按 life events 做结构化检索，另一层用 agent-specific parametric memory 把经验写进参数里。作者把这套纵向记忆框架叫 LifeMem，目标不是给角色补背景，而是让同一个 agent 随时间带着经历变化。

摘要只给出定性结果：在 Add Health 和 Understanding Society 上、用三个 LLM，LifeMem 改善了 response distributions、overall 和 within-group diversity，以及跨 life stages 的 within-person response change 模式。没有看到具体指标、提升幅度或和哪些基线相比，无法判断收益有多大。

这篇工作对社会模拟更接近“记住人会变成什么样”，而不只是“记住人属于哪一类”。对 agent 方向也有用：它把 memory 从临时上下文提升到纵向状态，但摘要里还没证明这种 parametric memory 的代价、可迁移性和是否会引入新偏差。

Static-profile LLM agents often turn demographic labels into essence: they exaggerate between-group separation while compressing within-group variation, unlike real humans. The problem is not just weak prompting. Prompt-only memory is too transient to accumulate experience over time, so agents keep re-creating the same stereotype-shaped responses.

The key move is a two-layer longitudinal memory design. LifeMem combines structured retrieval over life events with agent-specific parametric memory that integrates experience into the model. The goal is not richer backstory, but an agent whose behavior can change as its life trajectory unfolds.

The abstract reports qualitative gains on Add Health and Understanding Society with three LLMs. LifeMem improves alignment with human data for response distributions, overall and within-group diversity, and within-person response change across life stages. But the abstract gives no metric values, no baseline numbers, and no ablation details, so the size of the effect is still opaque.

For social simulation, the contribution is to model people as temporally evolving rather than fixed demographic templates. For agents more broadly, it is a concrete attempt to move memory out of the prompt and into persistent state. The catch is that the abstract does not establish the cost, portability, or whether parametric memory introduces new biases.

智能体反复编码工具和技能 schema，但标准 prefix caching 只能复用前缀，遇到同一资源被不同组合、不同顺序调用时还是要重算 KV，浪费时间和显存。

Agentic LLMs keep re-encoding tool and skill schemas that recur across requests, but standard prefix caching only reuses contiguous prefixes. Once the same resources appear in different orders or combinations, the KV states are recomputed, so the system pays repeated inference cost for nearly identical structure.

ReCache attacks that by making resource representations cacheable on their own. Resource-wise attention removes cross-resource interactions and assigns resource-local positions, so each resource produces a composition-invariant KV block. A second stage then limits which layers and KV-head groups can see each resource, and keeps only invocation-critical fields through structural and semantic pruning.

On a benchmark built from seven public tool- and skill-use datasets, including resource-disjoint tests, resource-wise attention matches dense invocation performance at 82.3% versus 82.4% Inv-F1. The full framework cuts allocated KV-tensor memory by 92.43%, gives a 3.655x time-to-first-token speedup, and speeds attention by 1.423x.

The main result is that reusable schema encoding can be separated from selective resource access without much effectiveness loss. The weak spot is scope: the evidence is from an abstract-only report, so the exact benchmark construction, ablations, and failure modes are not visible here.

长程 LLM agent 只拿终奖时，GraphGPO 这类方法把信用压成按终点距离衰减的图回报，同一状态下的不同分支常被判成一样，成功路径里的中间状态也未必真在推进任务。ALFWorld 和 WebShop 里共享状态很多，但 final-goal distance 只能看“到终点有多远”，看不出“哪条路更像进展”。

关键动作是把 rollout 图里的中间状态当作候选 milestone/trap，再用局部证据给它们重新打分。MileGPO 先做 MD，从成功轨迹里找 milestone、从失败轨迹里找 recurring trap；再用 RCS 按经验可靠度加权；最后用 PCC 结合 local progress 和同状态分支对照，把 $\delta_t^+-\delta_t^-$ 加回 GraphGPO 回报。整个过程只改 step-level advantage，不加辅助模型，也不额外交互环境。

结果上，MileGPO 在 ALFWorld 和 WebShop 都优于重现基线。ALFWorld overall success 到 $94.60\%$，比 GraphGPO 的 $92.71\%$ 高 $1.89$ 个点；ID/OOD gap 只有 $1.69$，低于 GraphGPO 的 $3.78$ 和 GiGPO 的 $1.89$。WebShop 上它拿到 $90.29\%$ score 和 $78.58\%$ success，分别比 GraphGPO* 高 $2.05$ 和 $3.78$ 个点。

这说明收益不是单纯多做图聚合，而是把“距离终点”补成“局部进展 + 同状态分支对照”。但它也依赖 rollout 里有足够重复状态和可比较分支；若这类局部证据稀薄，PCC 和 BCC 的作用会变弱。方法本身还是 one-sided credit rule，不是 policy-invariant shaping。

Long-horizon LLM agents still get punished or rewarded only at the end, so methods like GraphGPO collapse distinct decisions into a distance-to-goal return. That makes sibling actions from the same state look identical, and it can treat a state visited on successful paths as progress even when it is just a detour. In ALFWorld and WebShop, the problem is not a lack of trajectories; it is that final-goal distance does not say which intermediate step actually moved the task forward.

MileGPO’s move is to turn the rollout graph into evidence for milestones, traps, and local preference. It first discovers candidate milestones from successful rollouts and recurring traps from failures, then reweights them by empirical reliability, and finally checks whether a candidate reflects local progress and whether its incoming branch beats sibling branches from the same source state. The shaped term is added as $\delta_t^+-\delta_t^-$ on top of the GraphGPO return, so the method changes step-level credit estimation without auxiliary models or extra environment interaction.

The headline numbers are clean. On ALFWorld, MileGPO reaches $94.60\%$ overall success versus $92.71\%$ for GraphGPO, and the ID/OOD gap drops to $1.69$ from $3.78$ for GraphGPO and $1.89$ for GiGPO. On WebShop, it gets $90.29\%$ score and $78.58\%$ success, improving over the reproduced GraphGPO* by $2.05$ and $3.78$ points, respectively.

The point is not that graphs are enough; it is that the graph needs local evidence to break ties. That also marks the boundary: if a task rarely revisits the same state or offers few sibling branches, PCC and BCC have less to work with. And because the correction is one-sided credit, not policy-invariant potential shaping, the mechanism is useful but not theoretically neutral.

Time-series pretraining still breaks at tokenization. Dataset-specific patch sizes plus separate FFNs fracture the representation space, while a globally fixed small patch creates bottlenecks and washes out local dynamics. The model is forced to choose between cross-dataset compatibility and within-series fidelity.

SATS makes patch size an explicit scale. It keeps scale-specific FFNs, pools tokens by patch size into $Y\in\mathbb{R}^{N\times D}$, and applies a scale-aware alignment loss that pulls mean prototypes together and pushes max anchors apart: $\mathcal{L}_{\text{sa}}=\mathcal{L}_{\text{close}}+\beta\mathcal{L}_{\text{far}}$, with $\mathcal{L}=\mathcal{L}_{\text{nll}}+\alpha\mathcal{L}_{\text{sa}}$. On top of that, hybrid masking alternates random and contiguous spans so reconstruction has to learn both local completion and long-range structure.

The experiments cover LSTF, GIFT-Eval, and Monash after pretraining on LOTSA. On zero-shot LSTF, SATS_B reaches 0.316 MSE versus 0.348 for Moirai_B, a 9.2% reduction, and the 14M SATS_S still tops the average table. HM does not transfer to decoder-only training, very small patches hurt more than larger ones, and the paper does not report further hyperparameter search or systems-level cost.
