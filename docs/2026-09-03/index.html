LLM 做智能体时仍被标准 chat interface 绑死：它只能看到公开历史，不能维护一份不暴露给对话的 hidden state。问题因此不是“会不会聊天”，而是能否在交互中持续持有秘密，并让公开回复始终和这份秘密一致。

关键动作是把这类任务定义成 Private State Interactive Tasks（PSITs），再给出一个 self-consistency testing protocol：把对话分叉，检查模型能否在不同分支里保持同一 secret，同时不把 secret 直接写进 transcript。作者还给出一个理论不可能性结论：只要智能体只能依赖公共历史，就不能同时满足“秘密留在 transcript 外”和“回复与固定 hidden state 一致”。

实验上，标准 chat-based LLMs 和 retrieval-based memory baselines 都没过测试，而且这个失败与 scale 无关。摘要还明确说，semantic retrieval 并不能带来真正的 state maintenance；它能找回文本，却不能替代理解里的私有工作记忆。

这篇工作的价值在于把“memory”拆开了：公开可检索的上下文不是私有状态。对需要隐藏变量、分支后续一致性或游戏式推理的 agent，这个缺口很关键；但摘要里还没给出任务规模、具体基准或私有工作记忆实现细节，只能先把结论当作概念性约束。

LLM agents are still trapped by the standard chat interface: they can only condition on public history, not on a private state that stays hidden from the transcript. The real question is therefore not whether they can converse, but whether they can carry secret state across interaction while keeping public answers consistent with it.

The core move is to formalize this as Private State Interactive Tasks (PSITs) and test them with a self-consistency protocol that forks dialogue branches. The protocol checks whether an agent can preserve the same secret across branches without revealing it in the transcript. The paper also states an impossibility result: if an agent is restricted to public conversation history, it cannot both keep the secret unresolved in the transcript and answer consistently with a fixed hidden state.

Empirically, standard chat-based LLMs and retrieval-based memory baselines fail this test, and the failure does not disappear with scale. The abstract is explicit that semantic retrieval does not give true state maintenance; it can recover text, but it does not substitute for a private working memory.

The practical takeaway is that memory for agents splits into two different things: retrievable context and private state. That matters for any agent that must reason over hidden variables, branch consistently, or play games like Hangman. The limit is that the abstract gives no task sizes, benchmark details, or implementation specifics for the proposed private-memory architecture, so the result should be read as a conceptual constraint rather than a full systems recipe.

long-term memory 系统通常先抽取再检索，但“写什么进 persistent memory”这一步一直含糊。统一的 salience 抽取把同一套重要性标准套到不同 task、topic、activity、partner 上，结果是把偶然细节也写进去，和真正要保留的内容抢位子。

AdaMem 把问题改成 preference-conditioned write control：为每个 interaction context 维护一份自然语言 Memory Policy $\mathcal P$，抽取时用 $E(C_i,\mathcal P)$ 决定写入，反馈再用 $\mathcal P_{j+1}=U(\mathcal P_j,H_j)$ 更新它。核心是把 policy learning 和 policy execution 拆开，先学规则，再看 extractor 是否照做。

AdaMem-Bench 用 $5$ 个十周故事、每个故事 $6$ 个 persona、每周 $10$ 次 dialogue 和 $10$ 个 QA。平均看，AdaMem 把 Mem0 的 QA accuracy 从 $80.0\%$ 提到 $84.35\%$，persistent memory 从 $401.7$ 降到 $364.4$；Extraction F1 从 $35.0$–$45.1$ 提到 $40.1$–$47.2$，Recall@5 从 $54.2$–$67.8$ 提到 $64.6$–$73.4$。

这说明写入控制本身是独立杠杆：它能让答案更准、记忆更紧，但模型仍只拒绝约 $18\%$–$20\%$ 的 distractors，learning-to-execution gap 还在。再加上 benchmark 仍是合成、围绕 recurring persona，且评分依赖 LLM judges，外推到真实个人助理还不稳。

Long-term memory systems usually optimize retrieval after the fact, but they leave the write decision underspecified. A uniform salience extractor treats importance as context-free, so incidental details from one partner, task, or activity end up competing with the facts a user actually wants preserved.

AdaMem turns that into preference-conditioned write control. It keeps a scope-specific natural-language Memory Policy $\mathcal P$, feeds it into extraction as $\mathcal M_i=E(C_i,\mathcal P)$, and revises it from interaction history with $\mathcal P_{j+1}=U(\mathcal P_j,H_j)$. The design separates policy learning from policy execution: one component learns what should be remembered, the other tests whether the extractor follows that rule on later conversations.

The benchmark, AdaMem-Bench, contains $5$ ten-week stories, each with $6$ recurring personas, $10$ dialogue sessions per week, and $10$ QA items per week. Averaged over two extractors and two feedback modes, AdaMem lifts QA accuracy from $80.0\%$ to $84.35\%$ and cuts persistent memory from $401.7$ items to $364.4$. On the write pipeline itself, Extraction F1 rises across all four conditions from $35.0$-$45.1$ to $40.1$-$47.2$, and Recall@5 from $54.2$-$67.8$ to $64.6$-$73.4$. Under explicit feedback, policy alignment reaches $95.0\%$ by Week 10 from $53.3\%$ in Week 1.

The important takeaway is not that smaller memory is automatically better. The paper shows a real compactness/quality trade-off improvement, but the model still rejects only about $18\%$-$20\%$ of planned distractors, so the learned policy is not executed cleanly. The benchmark is also synthetic and persona-structured, and the evaluation depends heavily on LLM judges, so the gap to open-ended personal assistants remains real.

LLMs do not just make mistakes; they let those mistakes propagate because autoregressive decoding advances state without checking intermediate reasoning. That leaves no built-in way to catch a bad step before it contaminates everything downstream.

The move here is to turn inference into predicate-gated state transitions. 现有 LLM agent 在短基准上看起来稳，到了生产里的长、多步工作流就开始塌。问题不只是“会不会做对”，而是任务 horizon 一拉长，依赖步骤累积后，成功率会怎么坏掉，以及是上下文长度还是步数在主导。

Short benchmark runs make LLM agents look better than they are. The failure mode here is not a one-off mistake; it is horizon growth. Production workflows chain many dependent steps, so the relevant question is how reliability compounds as the trajectory gets longer.

The main move is to fit success as geometric decay with a single per-step reliability parameter. That parameter improves with scale but saturates below 1, so long horizons eventually collapse even for strong models. The study then varies four task families, five horizons, and three context regimes to separate step count from context length.

The abstract reports nine models in total: six open models from 1.2B to 671B parameters and three deployed proprietary systems. On a genuinely agentic tool-use loop, every model tested drops from near-perfect success to near zero within 16 steps across $n=10,664$ analyzed trajectories. Capping the context window steepens decay instead of easing it, with logit slope changing from $-0.44$ to $-0.69$ and $p=3\times10^{-6}$, which cuts against a lost-in-the-middle story. Projecting measured reliability onto benchmark horizons gives $0.42$ at GAIA-length horizons versus $0.24$ at hundred-step production horizons.

The useful takeaway is operational: evaluate agents by horizon, not aggregate pass rate, and budget reliability per step. The limitation is also clear from the abstract alone: the evidence is broad but still controlled, and the strongest claim rests on trajectories from the authors' own study rather than a full production log corpus.

现有 self-evolving memory 把最终 outcome 直接写回共享 memory，问题在于同一次成功或失败可能同时受 plan、execution 和环境影响。结果是执行细节会被当成规划经验，噪声还会在后续检索里反复放大，long-horizon planning 越学越偏。

CHIME 的关键动作是先判责再入库。它把 memory 分成 planning bank 和 execution bank，按 stage-specific query 先检索、再用 value rerank；任务结束后，Credit Attribution Gate 读取 task、plan、trajectory、outcome 和 retrieved memories，把反馈归到 planning、execution、both 或 none，只把对应 bank 更新，避免跨阶段污染。

实验在四个 long-horizon benchmarks、两种 backbone 上做 Avg@3。Qwen3.5-Flash 的 eval 平均是 34.87%，强 baseline 是 31.91%；DeepSeek-V4-Flash 是 39.01% 对 35.33%。CHIME 还把 memory 数压到 129，而 A-MapReduce 有 3,585；Gate 的重复判责一致率最高到 97.9%，换成更强的 Qwen3.7-Flash 后还可再涨 2.25 到 3.12 点。

这说明问题不只是“记住更多”，而是“记住时先分清该记给哪一层”。但它仍依赖模型自我反思做 credit assignment，且只在四个 benchmark 和二元 success 信号上验证；如果反馈更细、环境更开放，稳定性和收益还要再看。

Existing self-evolving memory methods write every outcome back into one shared store. For long-horizon planning, that signal is too mixed: the same success can come from a sound plan, from executor recovery, or from environment luck, while a failure can be caused by any of the same. Once that mixture is stored, it gets retrieved again and again, so execution noise starts to look like planning skill.

CHIME's move is to separate credit before writeback. It keeps a planning bank and an execution bank, retrieves them with stage-specific queries, and reranks candidates with a value corrected for reuse count, $\widetilde{v}_i=v_i\frac{n_i}{n_i+\lambda}$. After each episode, a Credit Attribution Gate reads the task, plan, trajectory, outcome, and retrieved memories, then assigns credit to planning, execution, both, or neither. Only the attributed bank is updated, with confidence $\gamma_t$ scaling the update.

The experiments are solid, but they answer a narrow question. On four long-horizon benchmarks and two backbones, CHIME wins the Avg@3 averages: 34.87% on Qwen3.5-Flash eval versus 31.91% for the strongest baseline, and 39.01% on DeepSeek-V4-Flash versus 35.33%. It also keeps only 129 memories where A-MapReduce keeps 3,585, and repeated gate attributions agree up to 97.9% of the time.

The main lesson is that memory helps only if it is credited at the right level. The approach still depends on model self-reflection for attribution, and the paper only validates it with four benchmarks and binary success signals. That makes the mechanism persuasive, but not yet a general answer for richer feedback settings.
