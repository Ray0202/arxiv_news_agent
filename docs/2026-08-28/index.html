终端 agent 的问题不是不会做，而是 RL 训练太依赖合成环境。环境一多，域偏差和低保真 reward 也一起放大，结果学到的往往是脆弱的策略，换个 harness 或模型就掉点。

关键动作是把 RL 重点放在“会怎么决策”，而不是从头教新技能。作者提出 Agentic Compositional Generalization：RL 主要塑造高层行为，再去编排和路由 pre-training 与 SFT 已经学到的低层技能；因此 verifier 质量比单纯堆环境数量更关键。River 通过过滤低质量环境，并用 process-level behavior regularization 给 outcome reward 加约束来提高 reward 质量。

摘要给出的结果是：River 在四个 terminal-agent benchmark 上，成为评估过的 open-source RL-trained 8B 模型里表现最好的；跨 model family、scale、agent harness 和 RL objective 也能泛化。用少于 TMax 训练环境的 $30\%$，它在 Terminal-Bench-Lite 上平均把 RL gain 提高 $106\%$，在 Terminal-Bench-v2.1 上平均提高 $30\%$，覆盖 $2\text{B}$ 到 $27\text{B}$ 模型。

这篇的价值在于，它把“多造环境”改写成“先把奖励信号筛干净”。但证据目前只来自摘要，且主要是自家 recipe 相对 TMax 环境子集的比较；真正决定结论强度的 verifier 质量、正则项和环境过滤各自贡献，还看不到。

Terminal agents fail less from a lack of raw capability than from brittle RL training. When synthetic environments stand in for scarce real-user traces, domain gaps and low-fidelity rewards can train policies that do not transfer across models, harnesses, or tasks.

The core move is to treat RL as learning high-level decision behavior, not new domain skills from scratch. The paper calls this Agentic Compositional Generalization: RL should shape how the agent composes and routes skills already learned in pre-training and SFT. River operationalizes that idea by filtering low-quality environments and augmenting outcome rewards with process-level behavior regularization, so verifier quality matters more than sheer environment count.

From the abstract, River is reported as the best open-source RL-trained 8B model among the evaluated systems on four terminal-agent benchmarks. It also generalizes across model families, scales, agent harnesses, and RL objectives. Using under $30\%$ of TMax training environments, it improves average RL gains by $106\%$ on Terminal-Bench-Lite and $30\%$ on Terminal-Bench-v2.1 for models from $2\text{B}$ to $27\text{B}$.

The main contribution is the training recipe plus the generalization hypothesis behind it: reward quality, not just environment diversity, is what seems to move terminal agents. The catch is that this is still an abstract-only claim, so the exact ablations, the verifier design, and how much comes from filtering versus process regularization are not visible here.

SPT: Skills as Pre-Training Data for Agentic Language Models

SkillCorpus mid-training beats trajectory data on agentic tasks, with little general-performance loss.

现有 agentic LLM 多靠 tool-call traces 和 trajectories 做 post-training，但这类数据要有环境、执行和验证，成本高，而且一条轨迹只记录一次执行，不是可复用 workflow。结果是，模型学到的是“这次怎么做”，不是“这类任务该怎么做”。

SPT 的动作是把 multi-file skill packages 直接拿来做 mid-training：在 38,040 个清洗并去污染的 ClawHub 包上做 causal language modeling，并用 Reference Insert 把被引用的支持文件插到指令附近，尽量保住跨文件依赖。它还允许 skill data 和 general data 在固定 token budget $B$ 下混合为 $p_\alpha(x)=\alpha p_{\mathrm{skill}}(x)+(1-\alpha)p_{\mathrm{gen}}(x)$。

实验覆盖 MeCo-1.6B、Instella-3B、OLMo-3-1025-7B。SkillCorpus 在 24 个 agentic 对比里拿到 23 个第一；相对直接 SFT，agentic 平均提升 $9.11$–$24.96$，而 general 平均只变动 $-0.85$ 到 $+0.51$。$30\%$ skill 的混合在 Dolmino/SmolLM 上把 agentic score 提到 38.60/37.58；Reference Insert 也在 Table 2 和 GRPO 设定下保持优势。

这说明 skill package 的确携带可迁移的 workflow 知识，但它更像 mid-training 的补充块，不像能单独替代 general data。局限也很清楚：语料来自单一 ClawHub 社区，只测了 1.6B–7B 和一个 360M RL 设定，聚合 benchmark 也没拆开 tool selection、argument construction 或长时交互失效。

Agentic LLMs are still mostly trained on tool-call traces and full trajectories after pre-training. That supervision is expensive: you need environments, execution, and verification to make the data. It also captures one run of one task, so the model learns an episode, not a reusable workflow.

SPT shifts the unit of training to multi-file skill packages. It mid-trains on SkillCorpus, a cleaned set of 38,040 public packages from ClawHub, with plain causal language modeling before any behavior-oriented post-training. Reference Insert keeps the files a skill mentions close to the first mention in SKILL.md, so the model sees the instruction and its supporting resources in local context rather than as a flat concatenation. Skill data can also be mixed with general data under a fixed token budget, using $p_\alpha(x)=\alpha p_{\mathrm{skill}}(x)+(1-\alpha)p_{\mathrm{gen}}(x)$.

Across MeCo-1.6B, Instella-3B, and OLMo-3-1025-7B, SkillCorpus beats both general-data mid-training and trajectory mid-training. In Table 1 it wins 23 of 24 agentic comparisons. Relative to direct SFT, the four-benchmark agentic mean improves by 9.11 to 24.96 points, while the six-benchmark general mean shifts by only -0.85 to +0.51. Mixing in 30% skill data reaches 38.60 with Dolmino and 37.58 with SmolLM, and Reference Insert is the strongest file-assembly strategy in the ablation.

The result is not that skills should replace general corpora. The cleaner read is that they are a targeted mid-training source that injects reusable workflow knowledge before SFT or RL. The catch is scope: the corpus comes from one ClawHub community, the main study only covers 1.6B–7B backbones plus one 360M RL setting, and the benchmarks are aggregate scores rather than direct probes of tool-selection errors, argument mistakes, recovery, or unsafe actions.

自治后训练常把过去的更新经验直接复用，但同一条经验是否仍有用，取决于父模型、数据和训练阶段。把“曾经有效”当成无条件许可，会浪费算力；更糟的是，错误的子模型还会拖坏后续训练轨迹。

关键动作是把经验授权和权重更新分开：BCIT 先把一次观测到的效果绑定到其来源上下文，再检查适用条件，遇到命名的硬冲突就直接否决；若仍不确定，就先做一个有界训练试验获取当前状态证据。真正训练出的候选仍要走共享的采纳规则，只有已观测事件才写入记忆。

摘要只报告了一个 4B 模型在 finance reasoning、text-to-SQL 和 function calling 上的适配实验。作者说候选更新在不同上下文里呈现异质的 target 和 retention 效应；在匹配候选、证据和 compute 的条件下，BCIT 批准的有害更新更少，并且以相同预算拿到更高的最终模型质量。

这篇工作的价值不在某个单点指标，而在把“经验该不该复用”单独建成问题：自治后训练不只是在选更好的更新，还在决定旧证据何时失效。它的边界也清楚：只有摘要可见，且没有给出具体数值、消融或硬冲突定义，因而更像概念与原型结果的证明。

Autonomous post-training often reuses past update evidence as if success were context-free, but whether an update still helps depends on the parent model, data, and training stage. That shortcut can waste compute, and if a bad child is promoted it can also poison the next round of training.

BCIT separates experience authorization from weight updates. It binds an observed effect to the context that produced it, checks applicability conditions, vetoes candidates with named hard conflicts, and, when needed, runs a bounded training trial to get evidence about the current state. Fully trained candidates still go through a shared adoption rule, and only observed events are stored in memory.

The abstract reports experiments on one 4B model adapted across finance reasoning, text-to-SQL, and function calling. Candidate updates show heterogeneous target and retention effects across those contexts. Under matched candidates, evidence, and compute, BCIT authorizes fewer harmful updates and reaches higher final-model quality at equal budget than the evaluated alternatives.

The point is not a single benchmark score. It is the claim that experience reuse itself should be treated as a separate decision in autonomous post-training, because old evidence can stop being actionable after later training changes the parent model. The limit is obvious from the abstract: there are no exact numbers, no ablations, and no visible definition of the hard conflicts or the bounded trial.

Most multimodal forecasting papers still miss the point: they either drag an LLM into inference, which is expensive, or they use dataset-level prompts that flatten variable-specific meaning. The result is a model that still treats each channel as a number stream, even when different variates carry different units, behavior, and temporal roles.

SAGE's move is to turn CLIP into the forecasting backbone. A CLIP ViT-B/32 text encoder reads frequency-enhanced patches and variate tokens, while variable-wise gated attention injects semantic, behavioral, relational, and statistical views. When the variable count is at most 50, the model also renders each series as an image and uses the frozen vision encoder for training-only contrastive alignment.

The paper evaluates 8 long-term benchmarks plus M4. SAGE reports the best average MSE on 7 of 8 long-term datasets and the best average MAE on 6 of 8, with overall average MSE 0.331 versus 0.345 for iTransformer, a 4.1% drop. Removing vision alignment raises the six eligible datasets' average MSE from 0.343 to 0.348.

The idea holds up as a compact alternative to LLM-in-the-loop methods, but the gains are not free. The text side still depends on hand-built templates, and its benefit shrinks on high-dimensional datasets. The visual branch is only used when the variable count is at most 50, so the paper does not show that rendered-image supervision scales to the largest multivariate cases.

LLM 写代码时常在功能和安全之间互相伤害：直给提示词会把漏洞留在实现里，改成安全导向又容易把逻辑改坏。检索指南能补知识，但泛化规则还得生成器自己翻成任务特定实现；共享对话式多代理则把上下文越堆越长，角色也会互相污染。

MACGen 的动作不是再加一个 critic，而是把流程拆成 Planner、Security Advisor、Code Generator、Reviewer 四段，只传结构化 artifact，不传整段对话。Planner 先给功能步骤；Security Advisor 依据 CERT/OWASP 的标准库，把任务和草稿映射到 CWE groups，检索 top-$K$ 规则并合成任务特定约束；生成器再按计划和约束出代码，Reviewer 迭代修正，最多 $M=2$ 次。

在 CWEval 的 119 个任务、5 门语言上，MACGen 在 6 个 LLM 上都优于 Direct，平均 F&S@1 比 Direct 高 19.61pp，最佳到 70.59%。在 BaxBench 的 392 个任务、6 门语言上，平均 F&S@1 比 Direct 高 10.57pp；GPT-4o 与 GPT-4o-mini 的 F&S@1 分别到 31.12% 和 21.94%。消融显示去掉标准驱动生成、代码级生成或验证，F&S@1 都会掉；代价上，它在 25 个 Python 任务上用 220,916 tokens、$0.91、28.34s，远少于 INDICT 的 1,411,754 tokens、$4.68、213.44s。

这篇工作的价值在于把“安全知识注入”变成“接口约束下的分工”，对 agent 设计比对单纯 prompt 更有说服力。它也有限：多代理循环仍有额外推理成本，评测又绑定各 benchmark 的 CWE 范围和功能 oracle；而且作者没有把 static analyzers 或 penetration testing 并入流程，安全性仍主要靠 LLM 自己推理。

Code models still trade functionality for security: direct prompting can leave the bug in place, while security-first prompting often breaks the intended logic. Retrieval helps with generic advice, but the model still has to translate that advice into task-specific code. Shared-dialogue multi-agent setups have a different failure mode: the context grows, roles blur, and critics start echoing one another.

MACGen's move is to enforce separation at the interface. A Planner writes a functional plan, a Security Advisor maps the prompt and draft code to CWE groups, retrieves top-$K$ rules from a CERT/OWASP knowledge base, and turns them into task-specific constraints, and a Code Generator writes the final code under both the plan and the security constraints. A Reviewer then gives perspective-separated feedback, with at most $M=2$ refinement rounds, and only structured artifacts move between stages.

On CWEval, across six LLMs and five languages, MACGen beats Direct on average by 19.61 percentage points in F&S@1 and reaches 70.59% at best. On BaxBench, the average gain over Direct is 10.57 points; GPT-4o and GPT-4o-mini reach 31.12% and 21.94% F&S@1, respectively. The ablations support the design: removing standards-driven generation, code-based generation, or validation hurts joint performance. In the cost study on 25 Python tasks, MACGen uses 220,916 tokens, $0.91, and 28.34 seconds, far below INDICT's 1,411,754 tokens, $4.68, and 213.44 seconds.

The main lesson is not “add more agents,” but “tighten the interfaces.” MACGen is more persuasive as an agent-design result than as a prompting trick, because it turns security into a staged constraint rather than a late critique. The limits are real: the multi-agent loop still adds inference cost, the evaluation is bounded by each benchmark's CWE scope and functional oracle, and the paper does not bring in static analyzers or penetration testing, so the security gain remains inference-time reasoning rather than verification.

摘要给出的结果很清楚：难度越高，对齐越差，而且在无 ground truth 时恶化速度约快 1.5 倍。困难样本上，6 个裁判都收敛到 77–82% 的窄区间，说明单靠模型规模碰不到结构上限。给了 ground truth 也不总是更好：GPT-5.4 降 1.5pp，Gemini-2.5-Pro 降 3.9pp。结构化 rubric 最多能提 6.5pp；chain-of-thought 和 judge temperature 几乎没用。

LLM judges are widely used for agentic tool-calling, but their reliability on structured workflows has been mostly unmeasured. Results from open-ended text or preference judging do not tell you whether a judge can follow dependency-heavy execution traces.

The paper’s move is to isolate that setting with AgentJudgeBench, a benchmark for LLM-as-a-judge on workflow DAGs. It contains 3,808 instances across six DAG topologies and three difficulty tiers, evaluated with five generators and six judges under paired conditions with and without ground truth.

The abstract reports a clear pattern: alignment falls monotonically as tasks get harder, and it degrades about 1.5x faster when ground truth is absent. On hard queries without ground truth, all six judges collapse into a narrow 77–82% band, which the authors read as a structural ceiling that scale alone cannot break. Ground truth is not always helpful: it reduces alignment for GPT-5.4 by 1.5 pp and for Gemini-2.5-Pro by 3.9 pp, consistent with over-anchoring. Structured rubrics help by up to 6.5 pp, while chain-of-thought and judge temperature barely move the needle.

The takeaway is practical: judge quality here is limited by task structure, not just model size. That matters for anyone evaluating tool-calling agents, but the evidence is still abstract-only, so the exact per-topology behavior, the human validation protocol, and the robustness of the rubric gains remain out of view.

现有 LLM agent 做时间序列异常和根因分析，常在真实系统里看起来能用，但缺少受控评测：到底是读懂了动态系统，还是碰巧猜对了，外部并不知道。

LLM agents are being used for time-series anomaly and root-cause analysis, but prior evaluations do not isolate what they actually learn from the signal. In real systems, a good-looking answer may hide brittle heuristics, and uncontrolled data make it hard to tell whether the agent understood the dynamics or just matched patterns.

TraceBench’s move is to turn root-cause attribution into a controlled simulation task. The agent sees observations from a simulated physical dynamical system and must decide whether one system parameter changed during the run, and if so which one. The benchmark generates tasks from three interpretable mechanical systems and compares four LLM agents across controlled conditions.

The abstract reports two clear effects. First, agents benefit substantially from domain context. Second, they inspect the data mainly through numerical console output rather than visualizations. It also says agents do worse when they must emit a Python script that maps each time-series sample to a root-cause label than when they can submit predictions directly.

The value here is not a new model, but a test harness that exposes failure modes of agentic time-series analysis. The limitation is equally clear: the claim is about three mechanical systems in simulation, so the benchmark measures controlled attribution, not full real-world troubleshooting. The abstract does not report the absolute scores, so the size of the gap is still opaque.
